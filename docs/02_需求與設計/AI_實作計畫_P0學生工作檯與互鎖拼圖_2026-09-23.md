# P0 學生主工作檯與互鎖拼圖 Implementation Plan

> **給代理開發者：** REQUIRED SUB-SKILL: 使用 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development` 逐項執行本計畫。每個步驟使用 checkbox 追蹤，先寫失敗測試，再寫最小實作；本文件只描述計畫，撰寫本文件不修改應用程式程式碼。

**Goal:** 在既有 Flask 學習歷程 P0 基礎上，完成單一學生工作檯的「上傳 → 同意與分析 → 人工確認 → 8 塊互鎖拼圖 → 可編輯自傳／學習計畫 → Word 匯出」流程，並保留 BYOK 與公開資料覆核發布的最小可驗收邊界。

**Architecture:** 保留現有 Flask Session、SQLAlchemy、Blueprint 與 `learning_profile` 模組；新增明確的 Consent、Provider、Storage、Puzzle、Draft、ApiKey 與 PublicSource 邊界，避免路由直接呼叫 Gemini、直接暴露私有檔案或把未確認資料寫成正式證據。學生主工作檯以一個頁面整合既有成果資料與新 P0 狀態，拼圖資料由已確認證據計算，未完成拼圖只顯示淡色空拼圖與下一步引導。

**Tech Stack:** Flask 3.0、Flask-SQLAlchemy、Flask-Migrate、既有 Flask Session／CSRF、私有本機 Storage Adapter、`python-docx`、pytest；個人保存金鑰使用伺服器端加密 adapter，單次金鑰只存在單次請求生命週期。

**Spec:** `D:\democase\ai\docs\AI_設計規格_測試版最終可實作規格_2026-09-23.md`

## Global Constraints

- P0 必須提供可操作的 8 塊互鎖拼圖：課程、作品、證照／技能、競賽／活動、專題、實習、反思、下一站；不得以線性節點、進度條或卡片清單冒充拼圖。
- 每次送出檔案至 Gemini 前必須有該次同意紀錄；原始文件、原始圖片、整份 PDF 與未去識別化個資不得送出。
- 本機規則解析與學生人工確認優先；AI 只能產生草稿，抵／免／補與畢業或錄取判定不可由模型定案。
- 身分驗證沿用 Flask Session；每個入口做伺服器端所有權檢查，不能依前端隱藏欄位判斷學生身份。
- 私有文件透過 Storage Adapter 存取與刪除；不得以靜態檔案路由、前端 HTML、測試資料、開發日誌或 Git 暴露原始檔案或 API 金鑰。
- Gemini Provider 必須可替換為 Fake Provider；逾時、429、額度不足或輸出不完整時，流程回到本機規則與人工確認，不阻斷學生完成資料確認。
- 系統共用金鑰、個人單次金鑰、個人保存金鑰三種行為必須在程式與測試中分開；保存金鑰只顯示末四碼，支援撤銷與替換。
- 公開資料只有經科辦明確發布後才可影響學生端「下一站」提示；未發布資料只顯示「偵測到新資料，科辦確認中」。
- P2 校園插畫、材質與動畫不列入本計畫阻塞項；`prefers-reduced-motion` 只需確保主流程可用，不得延後拼圖本體。

- 尚缺：逐次外送同意與遮罩版本、作品／競賽／專題／實習／反思／下一站資料、刪除撤回與快取清理、互鎖拼圖、可編輯草稿版本、BYOK、安全金鑰保存、公開來源差異與科辦發布流程。
- 既有 `Portfolio`／`PortfolioEvidence`／審查流程不重寫；P0 以證據連結 adapter 讀取既有成果，避免把學習歷程工作檯與送審流程混成同一個狀態機。

- 未勾選本次同意仍嘗試使用 Gemini：測試必須確認 Provider 不會被呼叫，且文件可以改走本機流程。
