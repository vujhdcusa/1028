# 資管科智慧學習歷程核心流程設計

## 目標

把目前的 Flask 骨架擴充成一條可驗收的核心流程：統一角色權限、建立專題與成果要求模板、讓學生安全提交作品、讓教師／科辦完成審查與補件版本，並提供不會直接修改正式結論的 AI 初檢介面。

## 範圍與原則

- 正式角色只有 `student`、`teacher`、`staff`、`admin`。
- `reviewer` 不再是登入角色；專題審查由既有教師共同討論，`staff` 登錄共同結論。
- 學生只能存取自己的作品、證據與提交版本，以及自己所屬小組允許的資料。
- 教師只能查看被分派的提交並提供覆核意見。
- `staff` 可維護專題模板、建立小組、分派教師、登錄共同審查結論與補正項目。
- `admin` 可管理帳號、系統資料與日誌，但第一階段不開放任意程式或 SQL 執行。
- AI 只產生候選摘要、缺件提示或分析紀錄；不得直接修改正式審查結論、規則或提交狀態。
- 所有檔案使用私有儲存，下載時重新檢查授權；不使用可猜測的公開檔案 URL。
- 既有 `Portfolio` 保留，新增的版本／快照／審查資料以外鍵連接，不破壞既有資料。

## 資料模型

第一階段新增：

- `ProjectType`：專題類型、適用年度、啟用狀態。
- `RequirementTemplate`：類型所使用的年度成果要求模板。
- `RequirementItem`：模板下的單項要求、階段、必要性與排序。
- `ProjectGroup`：小組專題主檔、類型、年度、指導教師與狀態。
- `ProjectMember`：小組成員、分工與成員狀態。
- `StudentProjectAssignment`：學生或小組採用哪個模板與年度版本。

第二階段新增：

- `PortfolioGoalSnapshot`：提交時複製的要求名稱、內容與版本。
- `PortfolioSubmission`：作品提交版本、狀態與前一版本。
- `SubmissionEvidence`：提交版本與證據的關聯。
- `SubmissionAssignment`：教師對提交版本的分派。
- `ProjectStageSubmission`：小組階段成果與版本。
- `ProjectReviewResult`：共同結論、評語、補件項目、登錄者與時間。
- `ProjectRevisionRecord`：補正問題、學生回應、確認狀態與關聯版本。

第三階段保留既有 `AgentTask`，新增 service 層的規則式初檢結果格式；若需資料庫保存，再以獨立分析紀錄連結提交版本，不寫入教師正式結論欄位。

## 狀態流程

```text
portfolio draft
  -> submitted
  -> under_review
  -> approved
  -> needs_revision
  -> new submission version
```

AI 的執行狀態為 `pending -> running -> succeeded/failed`，AI 失敗時只能保存錯誤訊息，不得產生通過結論。

## HTTP 與服務邊界

- `app/routes/main.py` 維持首頁、登入、登出與角色導頁；角色判定集中在 helper。
- `app/routes/student.py` 負責學生作品 CRUD、證據、提交與私有下載。
- `app/routes/staff.py` 負責模板、小組與分派管理。
- `app/routes/review.py` 負責教師查看被分派提交、staff 登錄共同結論與補件。
- `app/services/portfolio_service.py` 負責所有權、提交快照與版本建立。
- `app/services/review_service.py` 負責分派、審查狀態與補件版本。
- `app/services/ai_service.py` 只負責建立與執行候選分析，不直接變更正式審查資料。

## 安全與錯誤處理

- 生產環境必須設定 `SECRET_KEY`；開發預設值只供測試。
- 初始化管理者密碼必須由環境變數提供，不在輸出中回傳密碼。
- 表單使用 CSRF token；測試環境可明確關閉 CSRF。
- 上傳檔案限制大小、允許副檔名與安全檔名，儲存於 `instance/uploads`。
- 所有下載先載入目前使用者，再檢查學生本人、被分派教師、授權 staff 或 admin。
- 未登入回傳 401，角色不符回傳 403，不以隱藏錯誤代替授權檢查。

## 測試策略

- 每個新增行為先寫一個會失敗的測試，再實作最小版本。
- 角色測試：四種角色導頁、reviewer 拒絕、staff 可進入 staff 工作台。
- 所有權測試：學生不能讀寫他人作品；教師不能查看未分派提交。
- 快照測試：模板修改後既有提交快照不變。
- 版本測試：V2 不覆蓋 V1 的內容、證據、AI 執行與審查結果。
- 上傳測試：拒絕不允許格式、超過大小檔案與未授權下載。
- AI 測試：成功、失敗、缺件時均不改正式審查結論。
- 每個階段完成後執行完整 `pytest -q`。
