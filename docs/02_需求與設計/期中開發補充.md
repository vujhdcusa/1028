## 一、系統定位不變

本專題的完整定位是：協助五專資管科學生從一年級到五年級，持續整理與追蹤學習成果、證照、競賽、實務專題、校外實習、升學備審及就業準備，讓分散在不同地方的資料成為可查詢、可補強、可由教師回饋的學習歷程。

需求驗證顯示「教師逐份查看所有學習歷程並提供一般回饋」不足以作為主要使用動機，因此不再把它當成教師端唯一價值。教師／科辦端新增一條具日常行政需求的 P1：教師發布年度表單，學生下載填寫並電子回傳，教師初檢，科辦追蹤未繳／待補與正式行政狀態。

期中不縮減這個產品願景，而是先選出最能證明系統核心價值的一條流程。老師要求必須清楚展示「丟入什麼資料，系統產出什麼結果」，因此本輪的 P0 核心改為：

```text
學生登入
  → 上傳成績單與證照檔案
  → 系統擷取欄位並顯示給學生確認
  → 套用課程規劃與證照分類規則
  → 顯示課程摘要、待確認／補強項目與能力分類
  → 產生學習歷程摘要、自傳草稿與學習／入學計畫草稿
  → 下載 Word 文件
```

## 二、範圍分層

| 層級 | 定義 | 本專題內容 | 期中處理方式 |
| --- | --- | --- | --- |
| 長期願景 | 五年學習歷程的完整產品方向 | 學習、證照、專題、實習、升學／就業整合 | 保留於正式規格與產品定位 |
| P0 期中核心 | 必須能操作並可現場驗收的核心價值 | 成績單／證照上傳、可確認的欄位擷取、課程與證照分類、學習歷程摘要、自傳／學習計畫草稿與 Word 匯出 | 優先完成單一端到端流程 |
| P0 支援 | 為核心流程提供必要基礎 | 登入、角色權限、假帳號、附件安全存取、課程規則維護、操作紀錄 | 與 P0 同步完成 |
| P1 行政表單與人工確認 | 把紙本／Email 追件改成可追溯流程 | 教師表單發布、學生下載與電子回傳、缺件／補件、科辦進度與正式狀態；一般學習歷程回饋為支援功能 | P0 可操作後，優先完成不依賴 AI 的完整人工流程 |
| P2 體驗層 | 讓已確認資料形成個人化展示 | 五年地圖、拼圖作品集、下一站聚焦與公開首頁 | 必須連到 P0／P1 的真實資料 |
| Future | 需更多資料、規則或校方授權 | 正式校務介接、全自動 OCR、升學落點分析與進階推薦 | 不在目前承諾完成 |

## 四、期中核心驗收清單

| 編號 | 驗收項目 | 必須看到的證據 |
| --- | --- | --- |
| M-01 | 學生可登入並上傳成績單與證照 | 登入畫面、上傳畫面、檔案限制與安全存取紀錄 |
| M-02 | 系統可從檔案建立待確認的結構化欄位 | 成績課程列、成績／文字標記、證照名稱與日期等可編輯資料 |
| M-03 | 學生可確認或校正擷取欄位 | 原始檔、擷取結果、確認時間與校正紀錄均可回查 |
| M-04 | 系統依年度課程規則產生分類 | 通識／專業或能力類別、已修／待確認／可能補強項目及規則來源 |
| M-05 | `抵／免／補` 標記不被錯當成固定分數 | 顯示標記、解釋與「待規則／人工確認」狀態 |
| M-06 | 證照可被分類並連結原始佐證 | 證照欄位、類別、附件與來源可回查 |
| M-07 | 系統產生學習歷程摘要與下一步引導 | 輸入來源、已確認資料、待補資料與不可自行判定項目 |
| M-08 | 系統產生可編輯的自傳與學習／入學計畫草稿 | 草稿內容只引用已確認資料；資料不足時顯示缺漏，不捏造經歷 |
| M-09 | 學生可下載 Word 文件 | 下載的文件含學習歷程摘要與草稿，且可追溯產生來源 |
| M-10 | AI／規則失敗時不產生正式結論 | 可理解錯誤提示、保留原始資料與人工處理入口 |
| M-11 | 教師發布版本化行政表單 | 顯示年度、版本、指定對象、截止日、附件要求與發布者 |
| M-12 | 學生下載填寫並電子回傳 | 只能存取本人適用版本；提交與補件檔均可回查 |
| M-13 | 教師初檢、科辦追蹤正式狀態 | 教師不能核定抵免；科辦可查看未繳／待補並登錄正式行政狀態 |

## 六、文件與開發的同步規則

每次新增或修改功能，至少同步檢查以下項目：

- 正式規格書的功能分層與狀態標示。
- `diagrams.md` 中的流程圖、ERD 與角色名稱。
- Data Dictionary 的資料表、欄位與關聯。
- API Specification 的路由、角色與錯誤回應。
- 測試案例中的成功、拒絕與錯誤情境。
- `development-log.md` 的日期、修改檔案、測試結果與下一步。

任何未經科方或老師確認的收件期限、評分標準、正式校務資料與個人資料，均不得自行寫成確定規則。測試資料一律使用假帳號、假密碼與匿名附件。

## 七、目前版本判讀

截至 2026-09-23，既有 Flask 成果送審與角色功能的完整測試套件為 42 項通過；但 P0 的檔案欄位擷取、學生確認、課程／證照分類、草稿生成與 Word 匯出尚未完成。這些狀態應在期中交件中如實標示，不以規格書已描述來代替實作證據。

完整的日期、修改檔案、測試結果與階段狀態，請參閱：[期中完整開發軌跡](../03_開發紀錄/midterm-development-log.md)。

若要補充學校帳號、專題類型、成果繳交規則與公開資料來源，請填寫：[需求資料蒐集與規則補充表](./需求資料蒐集與規則補充表.md)。
