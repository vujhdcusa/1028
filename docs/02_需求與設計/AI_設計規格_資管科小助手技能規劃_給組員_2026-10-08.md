# 資管科小助手：技能（Skills）規劃與開發範例

> 對象：負責 AI 小助手的組員，以及他使用的 AI 開發工具（可以把整份文件直接交給 AI）
> 日期：2026-10-08
> 狀態：規劃範例，組員可以修改；**修改到「必須遵守」的部分前，請先和組長確認**

## 0. 給 AI 開發工具的開場指示（可直接複製）

> 你要在「資管科智慧學習歷程系統」（Flask＋SQLAlchemy）裡擴充現有的「資管科小助手」。請先讀本文件第 1～4 節，了解現有架構與必須遵守的規則，再依第 5 節的範例格式，為第 6 節列出的技能各寫一份技能規格，最後依第 8 節的順序實作。
> 不可以另外做一個新的聊天機器人，也不可以讓 AI 直接修改資料庫。每個技能都要附正常與異常測試，測試不能連網路（使用假的 chat 函式）。

## 1. 為什麼要這樣規劃

學長姐的專題審查紀錄（`school/Documents/專題審查學習目標與評量對照表.pdf`）裡，和 AI 小助手有關的教訓：

| 審查意見 | 對我們的要求 |
| --- | --- |
| EV3 教學：複評說「**AI 套件不熟**」 | 每個技能都要說得出：用途、用到哪些資料、限制、失敗時怎麼辦。評審問到時，負責的組員要能回答 |
| 共同目標 CLO3：「**不是互不相干的功能**」 | 小助手要查系統裡的真實資料（學生進度、校系加權、表單、獎狀），不能只是「把問題轉給 AI」的聊天框 |
| 權限與控制：「**未授權操作可被阻擋**」 | 學生只能查自己、導師只能查自己班、科辦只能查科辦的資料，而且要有測試證明 |
| 功能測試：「**每項核心功能至少一項正常及一項異常測試**」 | 每個技能至少兩個測試 |

所以小助手的重點不是「能接很多家 AI」，而是**「會用工具查系統資料、守權限、說得出依據」**。能切換 Gemini／GPT／Claude 是加分項，可以用來說明「換 AI 廠商不用改程式」（不寫死）。

## 2. 現有小助手的架構（已完成，在 `ai` 的 `main` 分支）

```text
使用者在網頁右下角提問
  → app/routes/assistant.py             接收問題（需登入）
  → app/services/assistant_service.py   ask()：Agent 迴圈，最多查 5 次
       ├─ system_instruction()          依角色產生系統提示（規則、頁面名稱、知識庫清單）
       ├─ assistant_tools.tools_for()   依角色取得可用工具
       └─ gemini_client.chat()          呼叫 Gemini（function calling）
  → 回傳 {answer, steps（用了哪些工具）, sources（引用哪些文件）}
```

| 檔案 | 內容 |
| --- | --- |
| `app/services/assistant_service.py` | Agent 迴圈、系統提示、工具執行、使用紀錄（`agent_tasks` 只記用了哪些工具，**不記問題與回答**） |
| `app/services/assistant_tools.py` | 工具函式與工具說明；`STUDENT_TOOLS`、`TEACHER_TOOLS` 兩個清單 |
| `app/services/knowledge_service.py` | 科上規定知識庫：搜尋 `app/content/knowledge/*.md`，不需要額外套件 |
| `app/services/gemini_client.py` | 只用 Python 內建 `urllib` 呼叫 Gemini；處理額度用完（429）、金鑰錯誤、連不上 |
| `app/templates/partials/assistant.html` | 前端對話框 |
| `tests/test_assistant.py` | 用假的 `chat` 函式測試，不連網路 |

目前的工具：

| 角色 | 工具（畫面上顯示的名稱） |
| --- | --- |
| 學生 | 查科上規定、查校系加權、查你的資料、缺件比對、自傳一致性檢查 |
| 導師 | 查科上規定、查校系加權、查本班學生、查學生資料、缺件比對、自傳一致性檢查 |

## 3. 必須遵守的規則

1. **只有一個小助手。** 組員做好的框架要整合進上面的架構，不要另開一套路由、另做一個對話框。
2. **工具只能讀，不能寫。** 不能新增、修改、刪除或送出資料，例如不能幫科辦按「核准」。要做的事改成回覆連結，請使用者自己到頁面操作。
3. **「是誰在問」由登入帳號決定。** 工具函式的第一個參數一律是 `user`（登入者），AI 不能指定要查哪個帳號。查學生時，用 `services/teacher_scope.py` 檢查權限。
4. **AI 不能做正式決定。** 例如畢業資格、抵免、錄取、獎狀核准、證照真偽，只能給「候選」或「提醒」，並說明以科辦或正式審核為準。
5. **回答要有依據。** 規定類的問題要引用知識庫，並列出來源；數字類的問題（進度、缺件、繳交人數）要用工具查，不能猜。
6. **隱私。** 對話內容不存資料庫；金鑰只放 `.env`，不 commit，錯誤訊息裡也不能出現金鑰。
7. **AI 不能用時要能說明。** 沒設定金鑰、額度用完或連不上時，都要回覆中文說明，不能讓頁面壞掉。

## 4. 多家 AI 的接法（組員框架要整合的部分）

目前 `assistant_service.ask()` 只依賴一個函式：

```python
chat(contents, tools, system_instruction) -> content
# contents: [{"role": "user"/"model", "parts": [...]}]   Gemini 格式的對話紀錄
# tools:    [{"name", "description", "parameters"}]      工具說明
# 回傳:     {"parts": [{"text": ...} 或 {"functionCall": {"name", "args"}}]}
```

建議做法：

- 新增 `app/services/ai_providers/`，裡面放 `gemini.py`（搬現有程式）、`openai.py`、`claude.py`。**每一個都提供同樣的 `chat()`**，在函式內把工具說明和回傳格式轉成上面的統一格式（各家的工具呼叫格式不同，以官方文件為準）。
- 用 `.env` 選擇廠商：`ASSISTANT_PROVIDER=gemini|openai|claude`、`ASSISTANT_MODEL=…`，以及各家的金鑰。**模型名稱不要寫死在程式裡。**
- `assistant_service.ask()` 改成依設定取得對應的 `chat`，Agent 迴圈和工具都不用改。
- 錯誤一律轉成 `AIUnavailable("中文說明")`。
- 盡量沿用 `urllib`。如果要加官方套件（例如 `openai`、`anthropic`），先和組長確認，再加進 `requirements.txt`。
- 測試：每一家寫一個「假回應 → 轉成統一格式」的測試，不連網路。

## 5. 技能規格的格式（範例）

「技能」＝一組**同一個目的**的工具，加上 AI 使用這些工具的規則。每個技能寫一份規格，格式如下：

```markdown
### 技能：<名稱>

| 項目 | 內容 |
| --- | --- |
| 給誰用 | 學生／導師／科辦 |
| 使用者會怎麼問 | 3～5 個真實問法 |
| 用到的工具 | 工具名稱、參數、回傳欄位 |
| 讀哪些資料 | 資料表或知識庫文件 |
| 權限 | 誰可以查什麼；越權時回覆什麼 |
| 回答格式 | 先結論、再重點；要不要附連結或來源 |
| 不能做的事 | 例如不能核准、不能判定資格 |
| 失敗時 | 查不到、沒資料、AI 不能用時怎麼說 |
| 測試 | 至少 1 個正常＋1 個異常（越權或查不到） |
| 答辯說法 | 一句話說明用途和限制 |
```

### 範例 A：查表單（學生、導師）

| 項目 | 內容 |
| --- | --- |
| 給誰用 | 學生、導師 |
| 使用者會怎麼問 | 「公假單在哪裡下載？」「實習要交哪些表？」「我的競賽報名表交了嗎？」 |
| 用到的工具 | `search_forms(user, keyword)` → `[{名稱, 分類, 類型, 下載連結, 截止日, 我的狀態}]` |
| 讀哪些資料 | `form_items`、`form_item_versions`、`form_collections`、`form_submissions`（見 `AI_設計規格_科辦表單區_下載與收件_2026-10-08.md`） |
| 權限 | 只列出開放給提問者角色的項目；「我的狀態」只查本人；導師可以查本班的繳交數字 |
| 回答格式 | 列出符合的表單和下載連結；需繳回的表單附上截止日和狀態 |
| 不能做的事 | 不能替學生繳交，也不能改狀態 |
| 失敗時 | 找不到時回覆「表單區沒有這份表單，請洽科辦」，不可以編出連結 |
| 測試 | 正常：學生問「公假單」，回覆有連結。異常：只開放給老師的文件，學生問了也查不到 |
| 答辯說法 | 小助手直接查表單區的資料，回答一定是系統裡真的有、而且使用者有權限看的表單 |

> 表單區的資料表還沒做好（排在下一個開發項目）。這個技能可以先寫規格和測試，等資料表完成再接上。

### 範例 B：科辦工作進度（科辦，新角色）

| 項目 | 內容 |
| --- | --- |
| 給誰用 | 科辦（`staff`） |
| 使用者會怎麼問 | 「現在有幾件電子獎狀等我核准？」「公假單還有哪幾班沒交齊？」「資管二乙誰還沒交？」 |
| 用到的工具 | `list_pending_certificates(user)`：待核准的電子獎狀（學生、事由、申請日）<br>`get_collection_progress(user, form_name)`：各班已交、應交、退件、未交人數<br>`list_missing_students(user, form_name, class_name)`：某班未交名單 |
| 讀哪些資料 | 電子獎狀申請（`feat/award-records` 分支，合併後才有）、表單收件資料 |
| 權限 | 只有 `staff`、`admin` 可以用；學生或導師的工具清單裡沒有這些工具 |
| 回答格式 | 先給總數，再依班級列出；附上「到收件頁處理」的連結 |
| 不能做的事 | 不能核准獎狀、不能退件（只能提供連結） |
| 失敗時 | 沒有待處理項目時，直接說「目前沒有待核准的申請」 |
| 測試 | 正常：有 2 件待核准，回覆 2 件。異常：學生帳號的工具清單沒有這個工具；用學生身分直接呼叫工具函式會被拒絕 |
| 答辯說法 | 科辦不用一頁一頁點，直接問進度；但核准和退件一定要本人在頁面上按 |

## 6. 技能清單與優先順序

| 優先 | 技能 | 角色 | 狀態 | 依賴 |
| --- | --- | --- | --- | --- |
| 1 | 多家 AI 切換（第 4 節） | 全部 | 組員框架整合 | — |
| 2 | 查科上規定（知識庫） | 學生、導師、科辦 | 已完成；**科辦要加入** | 補充知識庫文件（例如表單、獎狀規定） |
| 3 | 科辦工作進度（範例 B） | 科辦 | 待開發 | `feat/award-records` 合併、表單區 |
| 4 | 查表單（範例 A） | 學生、導師 | 待開發 | 表單區 |
| 5 | 電子獎狀申請狀態 | 學生 | 待開發 | `feat/award-records` 合併 |
| 6 | 已有技能補規格與測試：查你的資料、缺件比對、自傳一致性、查本班學生 | 學生、導師 | 已完成，補文件 | — |
| 之後 | 推薦校系、競賽報名統計 | 學生、科辦 | 等主線與競賽報名 | 指導老師決定推薦條件 |

建議的程式結構：新增 `STAFF_TOOLS`，並在 `tools_for()` 加上 `"staff"` 與 `"admin"`；`system_instruction()` 的 `ROLE_TEXT` 和權限說明也要加上科辦。技能多起來以後，可以把 `assistant_tools.py` 依角色拆成 `assistant_tools/student.py`、`teacher.py`、`staff.py`，對外的 `tools_for()` 不變。

## 7. 答辯時可以這樣說明（給組員準備）

| 問題 | 回答重點 |
| --- | --- |
| 小助手和一般 ChatGPT 有什麼不同？ | 它會用工具查本系統的資料和科上規定，回答附來源；查不到就說查不到 |
| AI 會不會看到別人的資料？ | 工具依登入帳號限制範圍，AI 不能指定帳號；有越權測試證明 |
| AI 可以幫忙核准或改資料嗎？ | 不行，工具都是唯讀，正式決定由本人在頁面上操作 |
| 為什麼可以換三家 AI？ | 為了不被單一廠商綁住；額度用完或價格變動時，改設定就能換，不用改程式 |
| AI 的限制？ | 免費額度有限、可能回答不完整；所以規定類一定附來源，數字一定用工具查 |

## 8. 開發順序與交付方式

1. **在自己的分支或 worktree 開發**，不要和其他人同時改同一個資料夾。建議分支名稱：`feat/assistant-providers`。
2. 先做第 4 節「多家 AI 切換」，跑過 `tests/test_assistant.py`，確認舊功能不受影響。
3. 依第 5 節格式，替第 6 節的技能 2～6 各寫一份規格，放在 `docs/02_需求與設計/`，**先給組長看**。
4. 規格確認後，一次做一個技能：先寫測試，再寫工具，最後把工具加進角色清單。
5. 每次修改都寫開發日誌 `docs/03_開發紀錄/development-log.md`（最新的寫在最上面）。
6. 交付時附上：測試結果（`pytest` 通過數）、改了哪些檔案、還沒做完的部分。

```powershell
.venv\Scripts\python.exe -m pytest -q tests/test_assistant.py
```
