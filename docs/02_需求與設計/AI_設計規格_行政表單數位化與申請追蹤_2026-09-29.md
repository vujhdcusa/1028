# 行政表單數位化與申請追蹤設計規格

> 狀態：已確認的 P1 需求修正基準
> 日期：2026-09-29
> 適用：團隊版與個人版
> 來源：多位指導老師指出原教師端「逐份查看學習歷程並提供一般回饋」的必要性不足；使用者補充校內紙本表單、證照／學分抵免等行政申請情境。

## 一、修正原因

原規格將教師端主要價值放在查看學生作品集、AI 報告與提供一般性回饋。這些功能可以保留，但不足以單獨證明教師會持續使用，也無法直接量化減少多少行政工作。

資管科官網目前已有[表單下載](https://im.ukn.edu.tw/p/412-1028-1192.php)，包含實習、專題、常用表格與相關法規分類；校內過去亦已有作業傳繳系統。因此本專題不得只複製「上傳檔案／下載檔案」，而要補上現行流程缺少的年度版本、指定對象、截止日、電子回傳、缺件、補件、狀態與操作紀錄。

## 二、產品決策

1. 保留 P0「學生上傳成績單／證照 → 校正確認 → 規則整理 → 文件產出」核心，不重新定義或刪除。
2. P1 主軸改為「行政表單數位化與申請追蹤」。
3. 教師一般性學習歷程回饋保留為支援功能，不再作為教師端唯一需求或主要展示論據。
4. 教師可建立並發布其負責班級或學生的已核准空白表單、填寫說明、適用年度、截止日與必備附件。
5. 學生下載指定版本、離線填寫，再以 PDF、Word 或清晰掃描檔回傳；不得強迫學生重新在網頁逐欄抄寫紙本內容。
6. 科辦／行政查看跨班級提交進度、未繳與待補名單，並登錄正式行政結果；不必逐筆代替教師上架表單。
7. AI 只做缺件、空白欄位、版本或年度疑義的候選提示，不得判定證照是否可抵免、核定學分或代替正式審查。

## 三、主要使用情境

以「當年度證照／競賽抵免申請」為示範案例：

```text
教師選擇表單類型與適用班級
→ 上傳已核准的空白表單與填寫說明
→ 設定適用年度、截止日與必備附件
→ 發布後保留不可覆寫的版本
→ 學生下載指定版本並離線填寫
→ 學生上傳填妥表單及證照／競賽佐證
→ 系統檢查格式、版本與附件完整性
→ AI（選用）產生缺件／疑義候選提示
→ 教師初檢並要求補件或轉交科辦
→ 科辦登錄收件、待補、完成或不受理等正式行政結果
→ 學生查看狀態與補件原因
```

同一流程可套用於實習、專題與其他常用行政表單，但每種表單的正式條件必須由授權人員依年度設定，不能由程式或 AI 猜測。

## 四、角色權限

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 學生 | 查看本人適用表單、下載指定版本、上傳填妥文件與佐證、查看狀態、依退補原因補件 | 查看他人申請、改表單版本、修改正式結果 |
| 教師／導師 | 建立草稿、發布本人負責範圍的已核准表單、設定說明與附件清單、查看指定學生、初檢與要求補件 | 修改他人發布內容、核定抵免學分、取代科辦正式行政結果 |
| 科辦／行政 | 管理表單類型與年度批次、查看全局進度、停用錯誤版本、匯出未繳／待補名單、登錄正式結果 | 代替評審或教務單位做未授權專業判斷 |
| 管理員 | 管理帳號、角色、系統設定、檔案限制與稽核紀錄 | 以技術管理權限偽造申請結果 |
| AI 分析服務 | 提示缺件、疑似空白、年度／版本不一致及無法辨識項目 | 自動核准、退件、給分、判定抵免資格或修改正式狀態 |

## 五、最小資料模型

| 資料表 | 用途 |
| --- | --- |
| `administrative_forms` | 表單名稱、類型、負責角色與啟用狀態 |
| `administrative_form_versions` | 學年度、版本號、原始檔、說明、檔案雜湊與發布者 |
| `administrative_form_assignments` | 指定班級／學生、開放與截止時間、必備附件清單 |
| `administrative_form_submissions` | 學生申請、使用版本、目前狀態、提交與補件時間 |
| `administrative_submission_files` | 填妥表單與各項佐證檔案 |
| `administrative_form_reviews` | 教師初檢、科辦正式結果、退補理由與操作者 |
| `audit_logs` | 沿用既有稽核表，記錄發布、下載、提交、補件與狀態異動 |

發布後的表單版本不可直接覆寫。修正內容必須建立新版本，既有提交仍指向原版本，才能回答學生當時下載及填寫的是哪一份文件。

## 六、狀態與防呆

建議申請狀態：

```text
draft → submitted → teacher_reviewed → staff_processing → completed
                  ↘ needs_revision ↗
                  ↘ not_accepted
```

- 截止後是否允許補交由該年度批次設定，不永久寫死。
- 同一學生、同一表單批次預設只有一筆有效申請；補件建立新版本，不覆蓋舊檔。
- 只能下載本人適用或授權範圍內的檔案。
- 副檔名、MIME、大小、安全檔名與惡意檔案掃描沿用現有上傳安全規則。
- AI 無法辨識時顯示「需人工確認」，不得把猜測寫入正式欄位。
- 抵免結果以學校正式程序與授權單位為準，本系統只管理表單、佐證、進度與可追溯紀錄。

## 七、與歷屆作品及現有網站的差異

| 現有能力 | 本系統新增價值 |
| --- | --- |
| 官網提供靜態表單下載 | 依年度、班級、負責教師與截止日發布正確版本 |
| 一般作業傳繳 | 針對行政申請建立狀態、補件、正式結果與稽核流程 |
| Email／紙本追件 | 系統產生未繳、待補及逾期名單 |
| 人工逐份確認附件 | 系統先檢查必要附件；AI 僅提供候選缺件提示 |
| 表單與學生歷程分離 | 已確認的證照、競賽或實習佐證可連回學生學習歷程，但不自動形成資格結論 |

## 八、P1 驗收標準

以匿名假資料完成以下流程，才可宣稱此功能完成：

1. 教師發布一份有年度、截止日與必備附件的表單版本。
2. 未被指定的學生無法查看或下載，取得 `403` 或不可見結果。
3. 被指定學生下載同一版本，回傳填妥表單與至少一份佐證。
4. 缺少必備附件時，系統明確提示且不得標示完成。
5. AI 關閉或失敗時仍能人工完成提交與審核。
6. 教師可留下初檢與補件理由，但不能寫入正式抵免結果。
7. 科辦可查看全局清單並登錄正式行政狀態。
8. 學生補件後，舊版與新版檔案、操作者與時間均可回查。
9. 表單發布、下載、提交、補件與結果異動均有稽核紀錄。
