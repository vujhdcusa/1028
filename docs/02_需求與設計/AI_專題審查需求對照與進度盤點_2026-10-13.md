## 給組員與指導老師的摘要

本專題有 Flask 後端、SQLAlchemy 資料模型、角色權限與 MySQL 連線設定，不是只有前端畫面。電腦上有 XAMPP 附帶的 MariaDB 10.4.27、MySQL 8.0.39 和 MySQL 8.4.9；正式專題規格指定 MySQL 8.0，因此建議開發以 MySQL 8.0.39 為主要驗收版本，保留 XAMPP，不要同時用兩套資料庫存同一份正式資料。

角色採「四種帳號角色＋關係範圍」：`student`、`teacher`、`staff`、`admin`。導師、專任教師、指導老師共用 `teacher`，由班級／指導關係決定能查看哪些學生；目前只把導師與班級關係列入本期實作。這次不新增校級管理員、平台管理員或多租戶角色，因為它們是商品化方向，並非這個學生專題的必要交付。

最新完整自動測試基線為 333 項通過；轉學生抵免、教師權限與遷移相關測試為 26 項通過（2026-10-13）。自動測試使用 SQLite 記憶體資料庫，不能當成 MySQL 8 實際連線驗收。隔離 MySQL 8.0.39 的本機通訊曾被 Windows 沙盒拒絕；尚未完成 MySQL 遷移實際驗收，也沒有操作既有資料庫服務。

按正式規格的 13 個 MVP 功能項目計數，目前有 12 項具備程式流程或測試證據，1 項「畢業門檻提醒清單」仍缺少可保存、可查看的學生流程。這是 **MVP 項目數的盤點比例 12／13（約 92%）**，不是整份系統規格、所有 12 月審核功能或 AI 延伸功能的整體完成率。報告時應說「MVP 主線 12 項已實作，畢業門檻清單待補」，並展示實際流程；不要把這個比例說成整個系統已完成 92%。

## 角色收斂與本期產品邊界

### 本期採用

- `student`：管理自己的學習歷程與升學準備資料。
- `teacher`：教師端共用角色；以導師班級關係限制學生資料範圍。專任教師或專題指導老師若未來有實際需求，再增加關係設定，不增加新的登入角色。
- `staff`：科辦業務，例如電子證明與行政待辦。
- `admin`：系統帳號、校系與規則等基本維護。
- 訪客可看公開展示頁，但不是登入角色，不列入學校要求的三種角色。

`staff` 和 `admin` 仍分開，因為科辦業務處理和帳號／規則管理的權限不同；這是現行系統明確的操作責任，不是為了商品化擴增角色。

### 暫不納入本期

提供的 25 點「可商品化系統規格」審查，適合作為未來產品化風險清單，不等於學校專題本期規格。以下項目不因該份分析而自動排入開發：多租戶、平台超級管理員、學校租戶管理員、計費、SLA、正式 SSO、雲端部署佇列、跨校資料隔離及多套商品模組。這些會顯著增加工作量，也不是本次學校要求的最低驗收條件。

目前應優先處理與專題審查直接相關的範圍一致性：MVP／後續版本標示、需求追蹤、實際 ERD、欄位級資料字典、資料庫連線證據，以及固定展示流程。

## 資料庫版本與驗收建議

- XAMPP 控制面板版本：3.3.0（截圖）。其中資料庫引擎版本以本機執行檔確認為 MariaDB 10.4.27，不是 MySQL 8。
- 獨立 MySQL 安裝：8.0.39、8.4.9。專題規格寫 MySQL 8.0，因此先以 8.0.39 作為可重現驗收目標。
- 目前埠 3306、3307 沒有資料庫監聽；Windows 服務狀態無法由本次工作權限查詢。兩套軟體可同時保留，但若要同時啟動，必須先確認各自埠號，避免佔用同一個埠。
- SQLite 測試已覆蓋資料模型、路由和 Alembic 遷移行為；正式報告前仍要在隔離的 MySQL 8.0.39 測試資料庫執行遷移、登入、CRUD、外鍵與回滾／備份驗收。
- 本次沙盒封鎖本機資料庫通訊，沒有對既有 MySQL／MariaDB 執行任何遷移、建表或寫入。
