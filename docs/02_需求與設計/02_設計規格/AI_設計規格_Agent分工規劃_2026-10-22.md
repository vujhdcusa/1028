## 〇、改版（2026-10-22 下午）：一個 Agent、多組工具

### 為什麼改

| # | 使用者 10-22 的意見 | 改法 |

| U3 | 分成五個 Agent 很難維護 | 只做**一個 Agent 引擎**，原本的 A1～A5 變成它的工具組；要加能力就加工具，不再做新 Agent |
| U4 | 還要讓學生生成自傳 | 自傳是同一個 Agent 的工具組（現有 AI 自傳小幫手），不另做 |
| U5 | 還有雲端 | 依 V2 架構提案（2026-10-16 指導老師與組員已同意）：Google Drive 是檔案倉庫，由系統把檔案存進去；Agent **不直接爬 Drive** |

### 引擎怎麼運作

- 沿用現有「資管科小助手」的做法（`app/services/assistant_service.py`）：AI 決定下一步 → 後端執行工具（檢查權限）→ 把結果交回 AI → 再決定，最多查幾次就停，最後列出用了哪些工具與依據。
- 抽成共用引擎（暫名 `app/services/agent_engine.py`），所有工具組共用：同一個執行迴圈、同一份執行紀錄（`agent_tasks`）、同一套 AI 額度與失敗回退（AI 不能用時改走規則結果或手動流程）。
- **兩種啟動方式，同一個引擎**：
  - **背景巡查**（排程，`flask agent-check`）：巡查招生與科規來源 → 有變更就擷取 → 產生候選資料 → 通知管理員或科辦核准。
  - **使用者觸發**（學生或導師在頁面上按）：讀學生資料 → 排序校系 → 寫理由 → 依選定校系寫自傳草稿 → 檢查自傳。結果嵌在頁面裡，不做自由輸入的聊天框（D5）。
- 規則不變：工具只能讀資料或產生「候選／草稿」；正式資料一律由人確認（學生、導師、科辦、管理員）。

### 雲端（T3，依 V2 架構提案）

- **方向是「系統存進雲端」，不是「Agent 爬學生的雲端」**：學生在網站上傳 → 後端存到 Google Drive（原始檔）→ MySQL 記檔案編號、類別、年級、狀態。
- **現在用自己的帳號測試**：沒有學校 Google Workspace 管理權限前，先用個人 Google 雲端硬碟驗證 API（V2 決策 3、V1 開發規格 D3）。檔案存放做成可替換的：V1 先存本機，Drive 測通後替換，其他程式不改。
- **正式導入時**：改用學校 Google Workspace，在學生自己的學校帳號建立一份備份。
- **Agent 的權限**：AI 不直接瀏覽 Drive；後端依任務只取需要的檔案與欄位，去識別化後才送 AI（V2 第 6、8 頁）。
- **學生已經放在雲端的舊檔案**：用 Google 選檔視窗讓學生自己挑要匯入的檔案（目前有單檔雛形），系統只拿得到被選的檔案；能否一次選整個資料夾還沒查證。
- 刪除先標記、送審版固定快照、依學校政策到期才永久清除（V2 第 7 頁）。


## 一、要做什麼（一句話）

把系統做成**升學媒合系統**：一邊從「學校」出發收集各校系的招生資料，一邊從「學生」出發判斷身分與資格，兩邊交集後，替學生把**所有**可能的學校排出建議順序，並**每一間都寫出理由**（包括不建議、不能報的）。另外由一個 Agent 持續追蹤**康寧大學資管科自己的規定**（畢業資格、認可證照），規定改了系統能跟著更新。

### A1 校系蒐集 Agent（擴充現有）

- **現在**：`admission_agent_service.py`。管理員登記來源 → 下載、比對雜湊 → 有變更就請 Gemini 擷取 → 候選 → 管理員核准。提示詞寫死「二技技優甄審」，只擷取評分項目與加權。
- **要改**：
  1. 提示詞依「招生管道」切換：二技甄審、二技統測分發、插大（轉學考）。
  2. 多擷取：報考資格、報名費、要交的資料、考科（插大）、時程、申請連結、地區（北／中／南／東）。
  3. 科系篩選關鍵字改成設定值（資訊管理、資訊工程、資訊科技、智慧商務……），不寫死「資管」。
- **輸入**：管理員登記的簡章網址或 PDF。**輸出**：候選校系資料（`status=candidate`、`data_origin=agent`）。
- **不做**：自己發布；下載整個學校網站。

### A2 資格判斷 Agent（新做）

- **做什麼**：整理「這位學生是誰、具備什麼」，給 A3 用。
- **輸入**：學生科別與年級、成績單 OCR 確認後的科目與成績、科上課綱（科目對應到哪個學群）、已確認的證照、競賽、活動。
- **輸出（學生條件摘要）**：
  - 學群：例如「資訊相關、商管相關」。
  - 已修過、通過的專業科目清單（對到課綱）。
  - 各類資料筆數、證照等級。
  - 「無法判斷」的項目（例如課名對不到課綱），標出來讓學生確認。
- **做法**：先用規則對照課綱；課名對不上時才請 AI 建議對應，並標成「待確認」，學生確認後才採用。
- **隱私**：送到 AI 的只有課名，不送姓名、學號；**缺曠資料不送外部 AI**。

### A3 媒合排序 Agent（新做）

- **做什麼**：對**每一個**正式校系，判斷能不能報、契合度多少，排出順序並寫理由。
- **步驟**：
  1. **資格篩選**（規則）：A2 的學生條件對照 A1 的報考資格 → 可報／不可報／需確認。
  2. **契合度**（規則）：沿用 `gap_service.analyze_gap` 的準備度公式（項目加權 × 完成比例），對全部可報校系計算。
  3. **活動分析**（T6）：學生的每一筆活動、競賽、證照，標出對到哪些校系的哪個評分項目。
  4. **排序**：可報的依契合度排列；不可報的放最後，不刪除。
  5. **寫理由**（AI）：每一間學校一段白話理由，例如「證照占 30%，你已有 2 張乙級」「台大沒有二技管道，可以考慮插大，需準備國英數與專業科目」。
- **輸出**：排序清單；每筆有「可報／不可報／需確認、契合度、理由、缺什麼」。
- **畫面提醒**：「契合度是依你目前資料和簡章加權算的，不是錄取機率；以招生簡章正式審核為準。」
- AI 額度用完時，仍顯示規則算出的結果，只是沒有 AI 寫的理由（10-10 規格第五節）。

### A4 小助手（調整現有）

- **現在**：`assistant_service.py`，有 5 個學生工具、6 個導師工具，最多查 5 次。
- **要改**：多一個工具「查我的推薦排序」（呼叫 A3），讓校系頁、推薦頁、缺件頁可以直接顯示 A3 的結果與下一步建議。
- 呈現方式依小助手規格 D1，嵌在流程裡，不新增聊天框。

### A5 科規追蹤 Agent（新做，沿用 A1 機制）

- **為什麼**：畢業資格和認可證照一直在變（U1）。現在的科規知識庫是用 `scripts/build_knowledge.py` 手動把科網頁、PDF 轉成 `app/content/knowledge/*.md`，規定改了要有人記得重跑，學生可能看到舊規定。
- **來源**：管理員登記康寧大學資管科的官方頁面與檔案，例如科網最新消息、課程規劃、畢業門檻公告、證照獎勵或認可清單（目前 `school/public-sources/` 已有的頁面先登記進去）。
- **流程**（和 A1 相同，共用 `PublicSource`／`PublicSourceChange`／`agent_tasks`）：
  1. 排程定期檢查（例如每週一次，`flask agent-check` 已有排程入口）→ 下載、比對內容雜湊。
  2. 有變更 → 建立「變更」通知管理員與科辦，並顯示新舊差異。
  3. 按「擷取」→ AI 擷取兩種結果：
     - **結構化規則**：畢業門檻（例如證照張數、等級、適用入學年度）、認可證照清單（證照名稱、等級、發證單位、適用入學年度）。
     - **知識庫段落**：更新對應的知識庫內容，讓小助手查得到新規定並附來源連結。
  4. 都先是候選；科辦或管理員對照原文核准後才生效（D7）。
- **誰會用到**：
  - A2：判斷學生已有的證照是否在「他那一屆」的認可清單、畢業門檻還差什麼。
  - A3、A4：缺件頁與首頁提醒「科上規定已更新」，只提醒受影響的入學年度。
- **不做**：自己發布；爬整個學校網站（只抓登記的頁面）；判定學生能不能畢業（以科辦正式審核為準）。

### 報考資格條件清單（A1 擷取、A2 準備學生資料、A3 檢查）

簡章裡常有不顯眼、但一不符合就不能報的條件（U2）。只靠「科系相關、加權」排序會漏掉，所以把資格條件拆成固定類型，**每一種都要能擷取、能檢查、資料不足時說清楚**。

| 類型 | 常見寫法（例） | 檢查要用的學生資料 | 系統現況 |
| --- | --- | --- | --- |
| C1 應屆／非應屆 | 「限應屆畢業生」「須於入學前取得畢業證書」 | 預計畢業年月（入學年度＋5，延畢另計） | 有 `admission_year`，**沒有延畢、提前離校的紀錄** |
| C2 學歷與同等學力 | 「專科畢業」「同等學力依教育部規定」；插大二、插大三要求不同 | 學制、已修學分、是否畢業 | 沒有 |
| C3 科系或群類限制 | 「限商業與管理群」「限資訊相關科系畢業」 | 科別、學群（A2） | A2 新做 |
| C4 統測考科 | 「須參加當年度統測某群類」 | 統測報考群類、是否當年度應考 | 沒有 |
| C5 技優資格 | 「乙級以上證照」「全國技能競賽前幾名」「證照須於某日前取得」 | 證照等級與取得日期、競賽名次與年度 | 有證照與競賽資料，**取得日期是否在期限內沒檢查** |
| C6 成績或排名門檻 | 「在校成績前 30%」「某科成績達幾分」 | 歷年成績、排名 | 有成績單 OCR，排名多半沒有 |
| C7 語言門檻 | 「英檢中級初試以上」 | 英檢種類、級別、日期 | 可放在證照類，未分出來 |
| C8 工作年資 | 在職專班、進修部「須有工作經驗幾年」 | 工作經歷 | 沒有；多數學生不適用，可先標「不適用」 |
| C9 身分與名額類別 | 原住民、身障、低收入戶外加名額或報名費減免 | 學生**自己勾選**的身分 | 沒有；屬敏感資料，見下方隱私 |
| C10 報名規則與衝突 | 「每人限報幾個志願」「技優甄審錄取後須報到，否則不得參加後續招生」「同一時段只能報一個管道」 | 學生已選的目標與管道 | 只有五年級最多 5 所目標的限制 |
| C11 時程 | 報名、資格審查、繳交證明的截止日 | 今天日期、學生已準備的資料 | 10-10 規格有公告時程，尚未和資格判斷連動 |
| C12 其他（原文） | 分不進上面類型的條件 | — | **一律保留原文，標「需確認」** |

規則：

1. **看不懂就不能當成符合**。A1 擷取不到類型的條件放 C12 保留原文；A3 遇到 C12，或學生缺檢查所需的資料時，結果一律是「需確認」，不是「可報」，理由寫明缺什麼（例：「這間限應屆畢業生，系統沒有你的延畢紀錄，請確認」）。
2. **每個條件都附簡章原文與頁碼或連結**，學生、導師能自己核對。
3. 應屆（C1）的算法先寫死一條規則：預計畢業年月＝入學學年度＋5 年的 6 月；招生學年度入學前會畢業的就是應屆。延畢、休學、提前離校由學生自己填、導師確認後覆蓋。
4. 時程（C11）：已過報名截止的管道標「本年度已截止」，仍顯示，讓低年級學生知道明年的時間。
5. 隱私：C9 身分**只由學生自己選擇是否填寫**，只用在系統內規則比對，**不送外部 AI**，畫面上也不顯示給其他學生；C6 排名、C9 身分只給本人與導師看。
