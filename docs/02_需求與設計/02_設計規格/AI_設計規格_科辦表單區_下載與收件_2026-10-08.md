# 科辦表單區（下載與收件）設計規格

> 狀態：**2026-10-09 更新：下載區（第十一點第 1 步）保留，排在 10-15 之後；收件功能暫停**（科助採訪與問卷都沒有出現收件需求）
> 日期：2026-10-08
> 取代：`AI_設計規格_行政表單數位化與申請追蹤_2026-09-29.md` 中與本文件衝突的部分（主要是「由誰上架」與「教師初檢」）
> 來源：2026-10-08 使用者決定（對話）；參考資管科網站表單頁 <https://im.ukn.edu.tw/p/412-1028-1192.php>

## 一、為什麼做

- 學生和老師要找科上的表單，現在要到資管科網站翻，而且網站上的表單不齊（使用者說有缺漏）。
- 需要繳回的表單（例如公假單、競賽報名表）目前靠紙本或 email，科辦要自己追「誰交了、誰沒交」。
- 學長姐「E 化學習平台」因為「班級課程不能自由新增」沒有通過複評（`school/Documents/專題審查學習目標與評量對照表.pdf` 第 4 頁）。所以本功能的分類、類型、要收哪些附件都**由科辦在畫面上設定，不寫死在程式裡**。

## 二、10-08 決定

| 項目 | 決定 |
| --- | --- |
| 誰上架 | **科辦**（`staff`）新增、修改、下架。09-29 版是「教師上架」，改掉 |
| 誰能下載 | 每個項目可勾選開放給**學生**、**老師**，或兩者 |
| 項目類型 | **參考文件**（只下載，例如科規、辦法）與**需繳回表單**（下載填寫後上傳回系統） |
| 繳回方式 | 學生填完後**上傳回系統**，科辦在系統裡收件，有收件清單、誰交誰沒交、退件 |
| 版面 | 收件清單**依班級分成可收合的區塊**，預設收合，避免頁面拉得很長 |
| 之後擴充 | 「需繳回表單」之後可升級成系統內線上填寫（像 Google 表單），給競賽報名使用；本版只預留，不做 |

## 三、角色能做什麼

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 科辦 `staff` | 管理分類；新增項目、上傳新版本、下架／重新上架；設定需繳回表單的對象班級、截止日、必附檔案；收件、退件（填原因）、標記完成；匯出未交名單 | 刪除學生已繳的檔案；覆寫已發布的版本 |
| 學生 | 下載開放給學生的項目；繳交指定給自己班級的表單；看自己的繳交狀態與退件原因；退件後補交 | 看別人的繳交；交不屬於自己班級的表單 |
| 老師 `teacher` | 下載開放給老師的項目；**導師可看自己班級的繳交情況（唯讀）**，方便提醒學生 | 退件、標記完成（這是科辦的事） |
| 管理者 `admin` | 和科辦相同（備用） | — |

## 四、畫面

### 4.1 表單下載（學生、老師共用）

- 選單新增「表單下載」。
- **依分類分成可收合的區塊**，每個區塊標題顯示項目數量，例如「實習（5）」。
- 上方有關鍵字搜尋，以及「全部／參考文件／需繳回」篩選。
- 每個項目顯示名稱、說明、版本日期、類型標籤。
- 需繳回表單另外顯示截止日和自己的狀態（未交／已交／退件，請補交／完成），並有「繳交」按鈕。

### 4.2 學生繳交

- 上傳填好的表單，以及科辦要求的附件（例如「證照影本」），每一項都會標示是否必附。
- 必附檔案缺少時不能送出，畫面會說明缺了哪一項。
- 退件時，學生會看到原因，並可以補交。補交是新的一輪，**舊檔保留**，不覆蓋。

### 4.3 科辦管理

- **項目清單**：依分類收合；可新增、編輯、上傳新版本、下架。
- **分類管理**：新增、改名、排序、停用（已有項目的分類不能刪除，只能停用）。
- **新增需繳回表單**時，另外設定：學年度學期、對象班級（可多選）、開放日、截止日、截止後是否還能交、必附檔案清單（名稱＋是否必附，可加多項）。

### 4.4 科辦收件頁（重點：依班級收合）

```text
公假單（114-1）  截止 10/31        [匯出未交名單] [匯出全部]
總計：已交 52／應交 90 ・待處理 8 ・退件 3 ・完成 41
篩選：(全部) (未交) (待處理) (退件) (完成)   搜尋：學號或姓名 [    ]

▶ 資管二甲　已交 30／45　待處理 5　退件 1　未交 15
▼ 資管二乙　已交 22／45　待處理 3　退件 2　未交 23
   學號        姓名    狀態      繳交時間     操作
   111534105  王小明  待處理    10/12 14:03  [看檔案] [完成] [退件]
   111534107  林小美  未交      —
   ...
▶ 資管三甲　……
```

- 每個班級一個收合區塊，**預設全部收合**；標題列直接顯示該班的數字，不展開也能看出哪班落後。
- 按篩選或搜尋時，只展開有符合資料的班級。
- 班內排序：待處理 → 退件 → 未交 → 完成。
- 用 HTML 原生 `<details>`／`<summary>` 做收合，不加前端套件；展開狀態用瀏覽器記住（讀寫失敗時不影響使用）。
- 導師看自己班級的同一頁（唯讀、只有自己的班級、沒有操作按鈕）。
- 同樣的收合寫法也用在 4.1 的分類區塊，以及之後競賽報名的名單頁。

## 五、狀態

```text
（未交：系統依對象班級算出，不存資料）
submitted 待處理 ──> completed 完成
     │
     └──> returned 退件（填原因）──學生補交──> submitted
```

- 同一位學生在同一份表單只會有一筆繳交紀錄；補交時新增「第 N 輪」的檔案。
- 截止後是否可交，看該表單的「截止後是否還能交」設定；逾期繳交會標示「逾期」。
- 本版不做「不受理」，有需要再加一個狀態值。

## 六、資料表（草稿）

| 資料表 | 主要欄位 | 說明 |
| --- | --- | --- |
| `form_categories` | 名稱、排序、是否啟用 | 科辦自行新增分類 |
| `form_items` | 分類、名稱、說明、類型（`reference`／`collect`）、開放學生、開放老師、是否上架、建立者 | 類型用字串保存，之後可新增（例如 `online`＝線上填寫） |
| `form_item_versions` | 項目、版本號、檔案路徑、原始檔名、檔案雜湊、上傳者、時間 | **發布後不可覆寫**；改內容就新增版本，學生下載的永遠是最新版 |
| `form_collections` | 項目、學年度學期、開放日、截止日、截止後是否可交、必附檔案清單（JSON：名稱、是否必附） | 只有「需繳回表單」才有。同一個項目每學期可以各收一次 |
| `form_collection_classes` | 收件設定、班級名稱 | 對象班級 |
| `form_submissions` | 收件設定、學生、狀態、輪次、最近繳交時間、退件原因、處理人、處理時間 | 同一收件設定＋同一學生唯一 |
| `form_submission_files` | 繳交、輪次、附件名稱、檔案路徑、原始檔名、上傳時間 | 每輪的檔案都保留 |
| `audit_logs` | 沿用既有表 | 記錄上架、改版、下架、繳交、退件、完成 |

和 09-29 版相比：表名改短，去掉「教師初檢」那一層；「學年度學期」放在收件設定上，對應審查意見「缺少學期屆別」。

## 七、安全與防呆

- 上傳沿用現有規則：副檔名與 MIME 檢查、安全檔名、單檔 10MB 上限。科辦上傳的表單可以是 PDF、Word、Excel、ODT；學生繳交可以是 PDF、Word、圖片。
- 下載前檢查身分：學生只能下載開放給學生的項目、只能看自己的繳交檔案；導師只能看自己班級的繳交檔案。其他情況一律回 403。
- 已下架的項目不出現在清單中，直接用網址也無法下載（403）；但學生已繳的檔案仍保留，科辦看得到。

## 八、和其他功能的連結

- **資管科小助手**：新增一個工具「查表單」，學生問「公假單在哪下載？」時會回覆連結；只會列出提問者有權限看的項目。
- **競賽報名（之後）**：會沿用這裡的分類、收件、班級收合和學年度學期。報名表要做成線上填寫時，`form_items.類型` 多一個 `online` 即可。
- **學習歷程**：本版不自動把繳交的檔案寫進學生的六類資料。

## 九、本版不做

線上填寫（Google 表單式欄位）、email 或站內通知、AI 檢查繳交內容、批次下載所有繳交檔案（ZIP）、教師上架。

## 十、驗收標準（每項都要有正常與異常測試）

1. 科辦新增分類與一份參考文件，只開放給老師：老師看得到、可以下載；學生看不到，直接用網址下載得到 403。
2. 科辦改上傳新版本：清單顯示新版本日期，舊版本的檔案仍可在後台查到。
3. 科辦建立需繳回表單，對象為資管二甲：二甲學生看得到並可以繳交；二乙學生看不到，也無法繳交（403）。
4. 缺少必附檔案時無法送出，並顯示缺了哪一項。
5. 截止後設定為「不可交」時無法繳交；設定為「可交」時可以交，並標示逾期。
6. 科辦收件頁依班級收合，標題列數字正確；篩選「未交」時只展開有未交學生的班級。
7. 科辦退件並填原因：學生看到原因、補交後狀態回到待處理，第一輪檔案仍保留。
8. 導師只看得到自己班級的收件情況，而且沒有操作按鈕；看別班的頁面會得到 403。
9. 匯出的未交名單 CSV 用 Excel 打開時中文不會亂碼（UTF-8 BOM）。
10. 上架、改版、下架、繳交、退件、完成都寫入 `audit_logs`。

## 十一、實作順序

1. 先做下載區：分類、項目、版本、開放對象、學生與老師的下載頁。這一步完成後就可以展示。
2. 再做收件：收件設定、學生繳交、科辦收件頁（依班級收合）、退件、補交、匯出 CSV。
3. 最後做導師唯讀頁與小助手的「查表單」工具。

開始前要先把 `feat/award-records` 合併回 `main`（科辦角色 `staff` 與科辦頁面在那個分支）。
