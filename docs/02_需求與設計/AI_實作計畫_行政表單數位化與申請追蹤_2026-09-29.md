# 行政表單數位化與申請追蹤 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立教師發布表單、學生下載填寫並電子回傳、教師初檢、科辦追蹤正式結果的可追溯 P1 流程。

**Architecture:** 新增獨立的行政表單領域模型與 `forms` blueprint，不把表單申請塞入既有作品送審資料表。檔案安全、Session RBAC、CSRF 與 `AuditLog` 沿用現有實作；AI 完整性檢查以可替換 service 提供候選提示，失敗時不阻塞人工流程。

**Tech Stack:** Python 3、Flask、Flask-SQLAlchemy、Flask-Migrate/Alembic、MySQL、Jinja2、pytest；選用既有文件分析 provider。

**Spec:** `docs/02_需求與設計/AI_設計規格_行政表單數位化與申請追蹤_2026-09-29.md`

## Global Constraints

- 不刪除或重新定義既有 P0 學生學習歷程核心。
- `student`、`teacher`、`staff`、`admin` 為既有登入角色；不新增 `reviewer`。
- AI 不得核准、退件、給分或判定抵免資格。
- 原始表單及學生附件採私有儲存，不提交 Git，不由公開靜態網址直接存取。
- 發布後的表單不可覆寫；修正必須建立新版本。
- 所有成功、拒絕、空資料與 AI 失敗情境必須有測試。
