# 圖表風格規範 Diagram Style Guide

> 專案：資管科智慧學習歷程系統  
> 用途：統一 Mermaid 圖表、報告圖片、簡報圖片與 BMAD AI Agent 產圖規則。  
> 原則：先產生 Mermaid 原始碼，再統一匯出圖片；避免每張圖各自生成造成風格不一致。

## 1. 使用目的

本文件用來規範本專題所有系統圖表的命名、層級、視覺風格與輸出方式，讓 Antigravity IDE、BMAD AI Agent、開發者與報告文件都能使用同一套圖表標準。

本專題圖表不以「華麗圖片」為主要目標，而是以「清楚、正式、容易修改、容易放入報告」為主。所有正式圖表應先保留 Mermaid 原始碼，再依需要匯出為 PNG 或 SVG。

## 2. 圖表製作總原則

- 所有圖表優先使用 Mermaid 作為原始格式。
- 不直接讓 AI 每次獨立生成不同風格的 JPG/PNG。
- 同一角色、同一模組、同一資料表，在所有圖中使用相同名稱。
- 每張圖只說明一個主題，避免一張圖塞入太多功能。
- 報告用圖片應由 Mermaid 統一匯出，確保風格一致。
- 若需要更精緻的圖片，必須先確認 Mermaid 版本正確，再進行美化。
- 圖表要能放進 Markdown、Google Docs、簡報與報告書。

## 3. 圖表清單與用途

| 編號 | 圖表名稱 | 建議格式 | 放置章節 | 用途 |
|---|---|---|---|---|
| D-01 | 使用者案例圖 | Mermaid flowchart 或 use case 圖 | 第三章 系統規格書 | 說明各角色可以使用哪些功能 |
| D-02 | 學生端流程圖 | Mermaid flowchart TD | 第三章 系統規格書 | 說明學生從登入到建立學習歷程的操作流程 |
| D-03 | 小組專題成果與共同審查流程圖 | Mermaid flowchart TD | 第三章 系統規格書 | 說明小組成果、教師共同討論、行政登錄與補正流程 |
| D-04 | 管理者維護流程圖 | Mermaid flowchart TD | 第三章或第四章 | 說明系統管理者維護帳號、資料與規則流程 |
| D-05 | 系統架構圖 | Mermaid flowchart LR | 第四章 需求分析 | 說明前端、後端、資料庫、AI Agent 與外部服務關係 |
| D-06 | DFD 資料流程圖 | Mermaid flowchart LR | 第四章 需求分析 | 說明資料如何在使用者、系統、資料庫與 AI 間流動 |
| D-07 | 權限矩陣圖 | Markdown 表格 | 第四章 需求分析 | 說明不同角色可執行的功能權限 |
| D-08 | AI Agent 任務流程圖 | Mermaid flowchart TD | 第四章 需求分析 | 說明 AI Agent 接收任務、分析、回傳建議的流程 |
| D-09 | ERD 資料庫關聯圖 | Mermaid erDiagram | 第五章 資料表結構 | 說明資料表之間的關聯 |
| D-10 | 報告用總流程圖 | Mermaid flowchart LR | 第七章 系統展示與功能說明 | 報告時用一張圖快速說明整體系統 |

## 4. 視覺風格規範

### 4.1 整體風格

- 風格：正式、乾淨、系統設計感。
- 避免：卡通風、手繪風、過多漸層、過度裝飾、過多陰影。
- 圖表背景：白色或極淺灰色。
- 線條：簡潔清楚，避免交叉過多。
- 節點：以圓角矩形為主，重要判斷節點可用菱形。
- 方向：主要流程使用由上到下 `TD`，系統架構使用由左到右 `LR`。

### 4.2 色彩規範

| 類型 | 建議顏色 | 用途 |
|---|---|---|
| 學生端 | 淺藍 `#DBEAFE` | 學生、學習歷程、作品上傳 |
| 教師 / 導師端 | 淺綠 `#DCFCE7` | 教師、輔導、共同討論、回饋 |
| 科辦 / 行政端 | 淺紫 `#EDE9FE` | 共同結論登錄、補正整理、行政維護 |
| 系統管理者 | 淺紫 `#EDE9FE` | 帳號管理、權限管理、系統維護 |
| AI Agent | 淺橘 `#FFEDD5` | AI 檢核、建議、分析任務 |
| 後端系統 | 淺灰藍 `#E0F2FE` | Flask、Service、API |
| 資料庫 | 淺灰 `#F3F4F6` | MySQL、資料表、資料儲存 |
| 外部服務 | 淺黃 `#FEF9C3` | GitHub、Google Drive、Gemini API |
| 警示 / 退件 | 淺紅 `#FEE2E2` | 審核失敗、缺漏、錯誤提醒 |

### 4.3 字型與文字

- 中文字型：微軟正黑體、Noto Sans TC。
- 英文字型：Arial、Inter、Noto Sans。
- 圖中文字以繁體中文為主。
- 可保留常見英文縮寫，例如 AI Agent、DFD、ERD、CRUD、API、MySQL。
- 節點文字應簡短，避免整段說明塞進圖裡。
- 建議每個節點 8～16 個中文字以內。

## 5. 名稱統一規則

### 5.1 角色名稱

所有圖表統一使用以下角色名稱：

| 標準名稱 | 不建議混用 |
|---|---|
| 學生 | 一般使用者、同學、User |
| 教師 / 導師 | 老師、評審帳號、Reviewer（評審是教師共同討論程序，不是帳號） |
| 科辦 / 行政 | 科助、行政帳號 |
| 系統管理者 | 管理員、Admin、最高管理者 |
| AI Agent | AI、小助手、智能助理 |
| 訪客 | 未登入使用者、Guest |

若文件中需要更細的角色，可在內文說明，但圖表中先維持一致。

### 5.2 系統模組名稱

| 標準名稱 | 說明 |
|---|---|
| 前端介面 | 使用者操作畫面 |
| Flask 後端 | 系統後端主程式 |
| 權限控管模組 | 登入、角色、權限檢查 |
| 學習歷程模組 | 學生作品、證照、競賽、專題資料管理 |
| 佐證資料模組 | 檔案、連結、證明文件管理 |
| AI Agent 模組 | AI 檢核、分析、建議產出 |
| 管理者維護模組 | 帳號、資料、規則、公告與系統維護 |
| MySQL 資料庫 | 系統主要資料庫 |
| 系統日誌 | 操作紀錄、審核紀錄、AI 任務紀錄 |

## 6. Mermaid 撰寫規範

### 6.1 流程圖 Flowchart

一般操作流程使用：

```mermaid
flowchart TD
```

系統架構圖或資料流向使用：

```mermaid
flowchart LR
```

### 6.2 ERD 資料庫關聯圖

資料庫關聯圖使用：

```mermaid
erDiagram
```

ERD 表名建議使用英文資料表名稱，欄位說明可在資料字典中補充。

### 6.3 權限矩陣

權限矩陣優先使用 Markdown 表格，不強制畫成流程圖。

建議格式：

| 功能 | 訪客 | 學生 | 教師 / 導師 | 科辦 / 行政 | 系統管理者 | AI Agent |
|---|---|---|---|---|---|
| 登入系統 | ✓ | ✓ | ✓ | ✓ | - |
| 管理學習歷程 | - | ✓ | 查看與輔導 | 共同結論登錄 | 管理 | 分析 |

### 6.4 節點命名範例

建議：

```mermaid
flowchart TD
    Login[登入系統]
    Dashboard[進入學生儀表板]
    Portfolio[建立學習歷程]
    Evidence[上傳佐證資料]
    Agent[送出 AI Agent 檢核]
    Result[查看檢核建議]
```

避免：

```mermaid
flowchart TD
    A[學生登入後進入系統然後可以建立資料也可以上傳很多東西]
```

## 7. 圖表拆分原則

不要只做一張很大的總圖。正式報告應拆成多張小圖，讓老師容易看懂。

建議拆法：

1. 使用者案例圖：看角色與功能。
2. 學生端流程圖：看學生如何使用系統。
3. 教師輔導與共同審查流程圖：看教師提供輔導、共同討論，以及科辦／行政登錄結論的流程。
4. 管理者維護流程圖：看系統如何管理與維護。
5. 系統架構圖：看前端、後端、資料庫、AI 的關係。
6. DFD 資料流程圖：看資料如何流動。
7. ERD：看資料表如何關聯。
8. 報告用總流程圖：上台簡報快速說明整體流程。

## 8. 報告圖片輸出規範

### 8.1 輸出格式

- 開發文件：保留 Mermaid 原始碼。
- 報告書：可使用 PNG 或 SVG。
- 簡報：建議使用 PNG。
- 若需要放大不失真：使用 SVG。

### 8.2 圖片命名

所有匯出的圖片放在：

```text
docs/images/
```

建議命名：

```text
D-01-use-case.png
D-02-student-flow.png
D-03-group-project-review-flow.png
D-04-admin-maintenance-flow.png
D-05-system-architecture.png
D-06-dfd.png
D-08-ai-agent-flow.png
D-09-erd.png
D-10-report-overview.png
```

### 8.3 圖片尺寸

- 報告書：寬度建議 1200～1600 px。
- 簡報：建議 16:9，1920 × 1080 px。
- 避免低解析度截圖。
- 不建議直接使用模糊的螢幕截圖當正式圖。

## 9. BMAD AI Agent 指令範本

### 9.1 產生 Mermaid 圖表

```text
請依照 docs/diagram-style-guide.md 的規範，為「資管科智慧學習歷程系統」產生 Mermaid 圖表。

要求：
1. 不要直接生成圖片。
2. 先輸出 Mermaid 原始碼。
3. 所有角色名稱需一致：學生、教師 / 導師、科辦 / 行政、系統管理者、AI Agent、訪客；「評審」僅在描述教師共同討論程序時使用。
4. 所有系統模組名稱需一致：前端介面、Flask 後端、MySQL 資料庫、AI Agent 模組、管理者維護模組。
5. 每張圖只表達一個主題。
6. 圖表需可直接放入 Markdown。
7. 圖表風格需正式、乾淨、適合專題報告。
```

### 9.2 修正既有 Mermaid 圖表

```text
請檢查 docs/diagrams.md 與主規格書中的 Mermaid 圖表，依照 docs/diagram-style-guide.md 統一以下項目：

1. 角色名稱
2. 模組名稱
3. 圖表方向
4. 節點文字長度
5. 圖表主題拆分
6. 是否適合匯出為報告圖片

請只修改 Mermaid，不要改動其他章節正文。
```

### 9.3 匯出報告圖片前檢查

```text
請在匯出圖片前檢查所有 Mermaid 圖表：

1. 是否能正常渲染。
2. 是否有語法錯誤。
3. 是否有角色名稱不一致。
4. 是否有節點文字過長。
5. 是否有箭頭交叉太多。
6. 是否符合 docs/diagram-style-guide.md。

檢查完成後，再依照圖片命名規則匯出到 docs/images/。
```

## 10. 本專題圖表內容建議

本專題的系統不應只呈現成簡單上傳平台，應凸顯以下系統深度：

- 多角色權限：訪客、學生、教師 / 導師、科辦 / 行政、系統管理者、AI Agent。
- 學習歷程管理：作品、證照、競賽、專題、實習、備審資料。
- 佐證資料追蹤：檔案、連結、來源、狀態。
- AI Agent 輔助：檢查缺漏、比對目標校系、產生補強建議。
- 管理者維護：帳號、權限、公告、目標校系資料、系統日誌。
- 資料庫設計：至少六張資料表，並具備關聯與正規化概念。
- 報告展示：能展示登入、學生操作、AI 檢核、教師查看、管理者維護。
