# 一、緒論

## 第一節 開發背景

五專學生在校期間會累積課程作品、專題成果、證照、競賽、實習經歷、成績資料及備審文件。這些資料常分散在個人電腦、雲端硬碟、GitHub、Canva 或紙本文件中，到了準備升學或備審資料時才重新搜尋與整理，容易耗時、漏件或產生文件內容不一致。

本系統以學生準備二技備審資料為主要需求，整理各年成績與學分、證照、活動、競賽、服務學習與幹部經歷，並依所選校系要求顯示缺少的資料。科辦提供電子證明與表單下載服務。

因此，本專題規劃建置「資管科智慧學習歷程系統」，以「選擇目標校系 → 收齊學習資料 → 比對還缺什麼 → 導師確認 → 產出完整備審資料」為主線，先完成主線流程，搭配文件辨識、學校資訊整理與操作引導。

本系統中的 AI 不取代教師、評審或管理人員做最終判斷，而是協助完成重複、耗時的初步查找與整理工作，並保留資料來源、分析理由及人工確認機制。

## 第二節 開發動機

歷屆相關專題已完成備審素材管理、二技校系資訊、志願序、履歷製作、成績單辨識、修業科目表、畢業資格檢核、招生問答與實習媒合等功能。若本專題只做檔案上傳、校系查詢、AI 問答或履歷文字潤飾，會與歷屆內容過度相似。

本專題將 AI 定位為輔助工具：在學習歷程中協助整理已完成、缺少與建議補強項目；也可協助辨識學生上傳的文件。AI 不能核定學分、資格、通過或退件，正式結果仍由學生確認或授權人員登錄。

在使用校園資訊的過程中，組員發現成績、獎懲、證照、競賽、服務學習與實習資料分散在不同網站。新生不容易知道應到哪裡查詢，也可能錯過公告或表單。本系統因此集中整理資訊入口，依年級提供提醒，讓學生更容易找到需要的資料。

## 第三節 開發目的

1. 建立資管科學生學習歷程的結構化管理機制。

2. 提供學生管理學習成果、備審 PDF、GitHub、Canva、證照、競賽、實習及佐證資料的功能。

3. 建立 AI 備審小助手，依目標校系或職涯方向整理已完成、未完成及建議補強資料。

4. 建立關卡式養成功能，將備審或履歷所需資料轉成任務卡。

5. 協助教師快速掌握學生學習歷程、作品、證照、專題成果與缺少項目。

6. 建立目標校系與職涯需求資料，由管理者整理並輸入系統。

7. 提供目標校系與職涯方向比較功能，但不預測錄取結果。

8. 符合資訊軟體開發組要求：關聯式資料庫、正規化、至少六張資料表、至少兩種非訪客角色、CRUD、統計、輸入防呆、檔案上傳、角色權限、系統架構、ERD、資料字典與需求檢核。

9. 調查並建立各目標校系的備審資料項目與採計標準；學生勾選校系後比對缺漏，並產出可列印的完整備審資料。

10. 提供科辦電子證明申請與表單下載服務。

# 二、開發環境

## 第一節 系統開發環境及使用工具軟體說明

**開發環境：**

**Windows 11**

Windows 11 是 Microsoft 推出的作業系統，本專題的程式開發、測試與展示都在 Windows 11 上進行。

**程式編輯軟體：**

**Antigravity IDE**

Antigravity IDE 是 Google 推出的整合開發環境，可以在同一個畫面編輯程式、管理 Git 版本與除錯，並內建 AI 輔助功能。本專題的程式都在 Antigravity IDE 中開發與測試。

**網頁技術：**

**HTML、CSS、JavaScript**

HTML 建立網頁的結構，CSS 設定外觀與排版，少量原生 JavaScript 處理表單檢查與畫面互動；本系統沒有使用 Bootstrap 等前端框架。

**後端程式語言與框架：**

**Python 3 與 Flask**

Python 是容易上手的程式語言；Flask 是 Python 的網頁框架，本系統用它處理登入與權限、檔案上傳、資料整理、缺件比對與備審資料產出。

**資料庫：**

**MySQL 8.0／SQLite**

MySQL 是關聯式資料庫，正式環境用來保存帳號、學習資料、校系備審要求、確認紀錄與操作紀錄；開發與自動測試時使用 SQLite，資料表結構相同。程式透過 Flask-SQLAlchemy 存取資料，資料表結構的變更用 Flask-Migrate 管理並保留紀錄。

**AI 服務：**

**Google Gemini API**

Gemini 是 Google 提供的生成式 AI 服務，本系統用來辨識上傳的文件並在確認畫面旁註記、擷取二技招生資料、撰寫推薦校系的理由與協助撰寫自傳。AI 的結果都要經學生本人、導師或管理員確認後才算數。

**文件產出：**

**python-docx**

python-docx 是產生 Word 檔的 Python 套件，本系統用它產出可列印的完整備審資料。

**測試工具：**

**pytest**

pytest 是 Python 的自動測試工具，每次修改程式都會執行全部測試，確認權限、資料確認與版本紀錄等功能正常。

**版本控制：**

**Git 與 GitHub**

Git 記錄每一次程式修改，GitHub 用來保存程式碼並和組員協作。

**圖表工具：**

**Mermaid**

Mermaid 用文字描述流程圖與資料庫關聯圖再輸出成圖片，流程有變動時只要修改文字就能重新產生圖。

**測試環境：**

**Google Chrome**

使用 Google Chrome 瀏覽器操作與檢查網頁畫面。

開發資料：使用測試帳號與模擬資料，不直接串接學校正式資料庫。

# 三、系統規格書

目前系統角色為學生、教師（導師、專任教師、指導老師共用教師端，以與學生的關係決定範圍）、科辦／行政（科助）、系統管理者與智慧輔助模組。系統管理者是開發者本人，與科助不同。導師負責備審資料確認；科辦／科助核准電子獎狀（科上派的服務、TA 證明、社團證明）並管理表單下載區，不審核備審資料。不另建立 reviewer 登入角色；專題審查不在本系統範圍（學校已有資管科畢業專題管理系統）。智慧輔助模組屬於後端輔助模組，可提供小助手介面，但不是登入角色，也不得取代任何人工審核權限。

### 五、轉學生需求補充

轉學生進入系統後，應能先看到「轉學生抵免申請輔助」入口。第一版不直接串接校方正式抵免系統，也不讀取正式校務資料；系統僅提供康寧大學抵免系統連結與人工紀錄欄位，協助學生與教師掌握是否已完成申請、是否需補交資料、申請日期與教師確認狀態。

校方抵免系統入口：https://ec.ukn.edu.tw/CT_web/login.aspx

本系統應清楚標示：抵免結果仍以學校正式系統與教務單位審核為準，學習歷程系統僅做提醒、整理與佐證資料管理。

## 第三節 非功能性需求

- 安全性：密碼雜湊、角色權限、後端驗證、安全檔案名稱。
- 個資保護：送往外部 AI 前遮蔽不必要敏感資訊；缺曠資料不送給 AI，只存合計，只有學生本人與班導看得到。
- 不刪除：公告只能下架、註解只能標「已處理」、自傳版本不能刪；重要操作寫進 audit_logs。
- 好維修：外部資料來源失效時在管理員頁面標紅，可換網址或手動輸入。
- 可追溯性：智慧輔助模組的結果保留資料來源、擷取時間、資料版本、分析狀態與人工確認結果。
- 可靠性：模型輸出需經 JSON Schema 驗證。
- 可用性：主要畫面支援桌機、筆電、平板，錯誤訊息需明確。
- 效能：較久資料整理模組任務採背景處理並顯示狀態。
- 可維護性：前端、後端、資料庫與 AI 模組分層。
- 公平性：智慧輔助模組不依無關資料評定學生，教師可駁回建議。

## 第五節 智慧輔助模組設計與限制

智慧輔助模組必須能接收任務、選擇允許工具、讀取資料、交叉比對、產生結構化結果、保存紀錄並等待人工確認，不只是聊天機器人。

主要模組：

1. 招生規則更新模組（系統亮點；主線的校系資料來源；擷取資格、文件、時程、加權、申請連結與學校特色）

2. 資料來源模組（資管科官網、資圖中心、教務處行事曆；只存文字與連結並擬分類，管理員核對）

3. 推薦校系理由（規則算出符合程度後，AI 只寫理由）

4. 文件辨識與確認畫面旁的註記（成績單、獎懲記錄、證照、電子證書）

5. 自傳小幫手（只引用確認過的資料）

6. 資管科小助手的限定範圍提問（只答操作、科上規定、個人進度，附出處）

7. 備審一致性檢核模組（後續擴充）

- 不得自行退件。
- 不得直接給予成績。
- 不得宣稱學生說謊或造假。
- 不得在沒有資料集時宣稱預測錄取率。
- 不得未經人工確認發布招生規則。
- 不得修改已發布表單、學生原始附件或正式行政狀態。
- 不得讀取缺曠資料。
- 不得回答限定範圍以外的提問。

## 第六節 需求可行性與驗收原則

第一版測試範圍應控制為三至五所主要二技學校，每校一至三個相關科系，保存至少兩個招生年度或規則版本，使用三至五份匿名測試備審資料。

核心驗收：

1. 是否完成指定任務完整流程。

2. 是否產生符合 Schema 的結構化資料。

3. 是否保存可開啟的原始來源。

4. 是否能辨識測試資料中的已知缺件或矛盾。

5. 管理員是否能核准或駁回候選更新。

6. 教師是否能採納或駁回系統提示。

7. AI 失敗時是否能顯示錯誤並保留人工處理方式。

8. 學生選擇目標校系後，是否能看到該校系的備審要求與自己還缺什麼。

9. 導師是否只能查看本班學生，並能確認內容或留下修改建議。

10. 資料齊全並經確認後，是否能產出可列印的完整備審資料。

11. 送審後學生或導師又存了新版時，導師的確認是否被伺服器擋下。

12. 管理員核准前，學生是否看不到自動化資料模組查到的招生資料與學校資訊。

13. 貼上成績、獎懲、缺曠是否解析正確、重複貼上不重複新增；缺曠是否只有本人與班導看得到、AI 的輸入資料裡找不到缺曠資料。

14. 首頁引導卡片是否不超過 3 張、做完後自動消失。

15. 科辦選單與網址是否都找不到「登錄送件審查結果」，舊資料仍在。

16. 操作紀錄頁是否只有管理員看得到，並能依使用者、動作、日期篩選。

各功能更細的驗收標準寫在 10-10 的各份設計規格裡。

# 附錄一、歷屆專題差異比較

## 第一節 歷屆專題比較

- 114 年「升學競賽全方位資源網」：備審素材分類、備審匯出、二技校系資訊、志願序及教師查看。
- 113 年「修業科目表管理系統」：修業科目表、替代課程、版本差異及畢業資格審查。
- 115 年「招生平台」：RAG 招生智能助手、招生資料管理、線上評分與來源連結。
- 115 年「智慧實習平台」：AI 履歷潤飾、成績單辨識、履歷審查及實習媒合。
- 114 年「軟丙軟乙學習平台」：術科自動批改、學習紀錄與教師統計。
本系統的主要差異如下：

1. 主線：選擇目標校系 → 收齊六類學習資料 → 比對缺件 → 導師確認 → 產出完整備審資料。

2. 整合而不重做：學校已有證照上傳、競賽報名、電子證書等系統，本系統把這些資料整合進備審，並以引導卡片、分類好的學校資訊依年級主動提醒。

3. 招生資料更新（系統亮點，第二、三階段已完成）：每年自動偵測二技簡章更新、擷取各校系備審加權並建立候選版本，管理者核准後才給學生使用；本系統保留資料來源與更新紀錄，供管理員核對。

## 第二節 專題定位與差異

本系統不是單純備審檔案平台、一般作業傳繳系統或只會回答問題的聊天機器人。核心價值是：

- 目標校系導航
- 關卡式養成
- AI 備審小助手
- 完整備審資料產出
歷屆專題主要著重資料保存、一般作業傳繳、文件製作、志願填寫、修業科目管理、履歷潤飾或招生問答；本系統把學生的五年學習資料、目標校系的備審要求與缺漏比對串成一條流程，最後產出完整備審資料。只有上傳與下載檔案不構成本專題差異。

和學校已有系統的差別：學校已有學生證照上傳管理、競賽活動報名、電子證書發證平台、服務學習課程記錄、實習週記與資管科畢業專題管理系統。本系統不重做這些系統，而是讓學生把各處的資料整合進來、對照二技校系的要求、由導師確認並產出備審資料，再加上依年級主動出現的引導卡片與分類好的學校資訊。

# 附錄三、分年學習歷程任務地圖與資料介接原則

## 第一節 分年任務

- 專一：建立基地，完成基本資料、帳號、GitHub、第一份課程成果與心得。
- 專二：累積證據，每學期建立課程成果並完成分類欄位。
- 專三：技能成長，整理證照、競賽、社團、服務或實作經驗。
- 專四：實習準備與經驗整理；專題方向、組員與指導老師媒合從專五開始。
- 專五：備審整合，二技公告、縮減到 5 所目標校系、完成自傳、送導師確認、補缺件。
各年級的任務會以引導卡片出現在首頁（一次最多 3 張，依年級＋時間點＋學生做了什麼），例如專一的「歡迎、認識二技、存第一份成果」、學期末的「網路成績只開放一週，現在去複製」。卡片方向見設計規格「引導卡片與科辦、管理員功能清單」。

## 第二節 任務完成原則

任務必須對應實際資料或證據，不得只以點擊按鈕作為完成條件。任務完成度用於協助整理與輔導，不直接等同學業成績或審查分數。

## 第三節 資料介接原則

專題開發不得索取、複製或直接連接學校核心資料庫。測試帳號、證照與成績單展示內容均使用去識別化假資料；不得使用真實姓名、學號、身分證字號或可回推個人的資料。

若日後正式導入，應由校方資訊單位提供唯讀 API、SSO 或去識別化資料。

學校成績、獎懲、缺曠資料由學生自行登入學校系統複製或下載後交給本系統（整段貼上表格或上傳檔案）；本系統不得保存學生的學校帳號密碼，也不得以學生帳號登入或爬取學校系統。網頁成績只開放約一週、標示「僅供參考」，正式以紙本成績單為準；期中已修畢的部分課程只有列印成績單才完整；微學分課程不會印在成績單上；學校沒有微學分系統，微學分要寫紙本向教務處申請，學生怎麼把證明放進本系統待確認。缺曠只存假別合計，不存逐日明細。

學校公開網站（資管科官網、資圖中心、教務處）只抓管理員登記的頁面，只存文字與連結，每頁間隔幾秒、每天或每週一次；名單類公告只存標題、日期、連結。

轉學生抵免系統採「外部連結＋人工紀錄」方式處理。本系統只放置校方抵免系統入口，並保存學生自行填寫的申請狀態、申請日期、抵免科目備註、需補交資料與教師確認狀態。系統不得擅自抓取抵免系統中的個資或審核結果。

畢業門檻、重補修、二技備審加權與專題評量資料，均以「提醒與佐證整理」為定位。正式畢業資格、抵免結果、補修學分、二技招生規定與專題成績，仍以學校、教務單位、招生簡章與指導老師/審查委員公告為準。
