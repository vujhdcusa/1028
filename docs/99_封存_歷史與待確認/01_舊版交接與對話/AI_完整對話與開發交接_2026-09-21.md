## 2. 對話與決策時間線

### 2.1 專案檢視與文件整理

使用者一開始要求檢視整份專案與 AI 交接摘要，並要求：

- 整理文件，所有後續 Markdown 統一置於 `ai/docs`。
- 檢查根目錄散落的 Codex、BMAD 與其他 AI Agent 套件。
- 將可移動的 AI 工具內容集中至 `D:\democase\agent`；VS Code 以 `files.exclude` 和 `search.exclude` 隱藏執行期或工具資料夾。
- 每次整理要記錄開發日誌，且說明如何在 VS Code 顯示／解除隱藏。

目前文件已分類為 `01_正式規格`、`02_需求與設計`、`03_開發紀錄`、`04_圖表與介面`、`05_交接與專案管理`。Git 顯示舊 `docs/` 根目錄檔案刪除、分類資料夾新增，是這次文件重整的正常結果，不是文件遺失。

### 2.2 UI／UX 決策

使用者提供參考圖片與對話稿後，明確要求：

- 不要「AI 味」或生硬直譯文案，改為台灣常見網路服務語氣。
- 不要過度整齊、過大留白或單調卡片牆；要有文字層次、內容密度與受控不對稱。
- 公開首頁與學生端需要更多動畫，否則太生硬。
- 教師、科辦、管理者後台則要低動畫、重資訊密度與操作效率。

已採用的 UI 主題為：`Piece × Path × Archive`，首頁主標是「把五年，拼成下一站。」詳細規格在 `docs/04_圖表與介面/02_設計規格/UI_UX_設計與動畫規格_2026-09-21.md`。

### 2.3 核心流程決策

- 角色固定為：`student`、`teacher`、`staff`、`admin`；`reviewer` 不可登入。
- 教師只能查看被指派的送件並留下意見。
- 科辦／行政與管理者才能登錄共同結論（核可、需要補正、退件）。
- 教師意見與科辦共同結論要分開保存，不能混成同一筆資料。
- 管理者可維護帳號狀態與年度化規則；目前不提供刪除已使用資料、刪除帳號或讓管理者停用自己。
- 未確認的學校正式期限、抵免、評分或校務資料不可被寫成確定規則。

## 3. 目前已完成的程式功能

### 3.1 基礎與安全

- Flask App Factory、SQLAlchemy、CSRF、檔案名稱安全檢查。
- 登入、登出、角色導向與角色權限檢查。
- 專案使用 `Flask-Migrate`；`app/extensions.py` 的 `migrate` 已在 App Factory 初始化。

### 3.2 學生流程

- 公開首頁、登入頁、學生首頁。
- 建立、編輯、送出學習成果。
- 私有佐證檔下載的擁有者檢查。
- 學生首頁會顯示成果數、五年路徑、下一塊拼圖與提示。

### 3.3 教師與科辦流程

- 教師可查看自己被指派的審查。
- 教師可提交非空白意見；未指派教師會收到 `403`。
- `TeacherReviewFeedback` 獨立保存教師意見。
- 科辦工作台可看到已送審成果與教師意見。
- 科辦可登錄 `approved`、`needs_revision`、`rejected` 的共同結論，送件狀態會更新。

### 3.4 管理者流程

- 管理總覽：帳號數、送件數、待處理數、最近送件。
- 帳號管理：可啟用／停用其他帳號，不能停用目前登入的管理者。
- 規則管理：可建立與啟用／停用專題類型、成果模板；可新增要求項目（階段、排序、說明、必填／選填）。
- 不提供刪除帳號或刪除已使用規則。

### 3.5 UI 實作

- 共用外殼：`app/templates/base.html`。
- 設計系統：`app/static/css/design-system.css`。
- 動畫：`app/static/js/motion.js`，使用 CSS 與 `IntersectionObserver`，支援 `prefers-reduced-motion`。
- 公開首頁、學生端是 Experience Layer；教師／科辦／管理者是 Work Layer。
