# 整合驗收與失敗回收規則

> 版本：2026-09-29

## 一、整合前檢查

- `git status` 已記錄，沒有不明來源的檔案變更。
- 組員功能測試通過。
- 完整測試可執行；若被環境或權限阻擋，必須記錄原因。
- 不含密碼、Token、API 金鑰、原始個資或原始上傳檔。
- migration 有 upgrade／downgrade 或明確回復方案。
- 文件、流程圖、角色名稱與實際路由一致。

## 二、P0 端到端驗收

匿名成績單／證照 → 非空擷取草稿 → 學生校正 → 規則分類 → 摘要／缺漏 → 自傳／學習計畫 → Word。

任何一段只能靠人工貼 JSON、空 fake provider 或無法回查來源，都不能標示為完成。

## 三、失敗回收

1. 停止後續合併，不在失敗狀態上繼續加功能。
2. 保存失敗測試輸出、錯誤日誌與變更 commit。
3. 回到上一個整合快照，不重設或刪除組員原始分支。
4. 將問題分類為程式、資料模型、環境、規格或整合衝突。
5. 修正後重新執行同一驗收案例，再允許下一次整合。
