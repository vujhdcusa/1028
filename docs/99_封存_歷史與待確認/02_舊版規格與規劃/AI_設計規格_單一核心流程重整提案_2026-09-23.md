## 2. 【BMM 專業結論】P0 可驗收使用者故事與例外情境

> **負責專家**：@BMM（流程管理專家）  
> **簽署日期**：2026-09-23  
> **核心目標**：確保學生經歷「上傳 → 校正 → 拼圖 → 自傳」四步驟時具備明確驗收依據，且任何異常輸入皆有閉環處置機制。

### 2.1 P0 核心可驗收使用者故事 (User Stories)

#### [US-01] 檔案安全上傳與格式驗證
- **As a** 五專資管科學生
- **I want to** 在學生主頁上傳我的成績單（PDF/圖片）、專業證照（PDF/圖片）、競賽獲獎證明或專題成果
- **So that** 系統能取得我這五年累積之原始佐證資料，且原始檔案獲得隱私隔離保護。
- **驗收條件 (Acceptance Criteria)**：
  1. 系統支援上傳 `.pdf`, `.png`, `.jpg`, `.jpeg` 格式，單檔限制在 10MB 以內。
  2. 上傳前必須主動勾選《個人資料自主授權與 AI 輔助處理同意書》；若未勾選，上傳按鈕維持禁用狀態。
  3. 檔案上傳後立即寫入學生私有隔離目錄，產生對應之 `document_id`，狀態初始為 `pending_analysis`。

#### [US-02] AI 結構化擷取與學生即時校正
- **As a** 五專資管科學生
- **I want to** 看到 AI 擷取出的課程科目、學分、成績、修課狀態（抵/免/補）或證照名稱與發照日期，並能在表單上即時修改
- **So that** 我能校正 OCR 辨識瑕疵，確保入庫資料 100% 正確，不被錯誤的 AI 幻覺影響學籍。
- **驗收條件 (Acceptance Criteria)**：
  1. AI 辨識結果必須先落入「待確認草稿區 (Draft Stage)」，嚴禁直接寫入學生正式學籍紀錄。
  2. 介面提供清晰之雙欄對照（左側檔案預覽，右側結構化可編輯表單）。
  3. 學生修改完畢並點擊「確認無誤」後，系統比對科辦維護之「當年度課程與領域分類規則」，打上通識/專業、必選修及修課狀態標籤，狀態轉為 `confirmed`。

#### [US-03] 成果映射至互鎖拼圖作品集
- **As a** 五專資管科學生
- **I want to** 在同一個主頁上看到我確認的成果自動拼入「我的五年拼圖」對應板塊，缺漏部分呈現淡色引導
- **So that** 我能清楚掌握自己累積了哪些具體能力，以及還缺少哪些佐證。
- **驗收條件 (Acceptance Criteria)**：
  1. 已確認之課程、證照、競賽、專題自動點亮對應之拼圖塊，並累加該領域完成度數值。
  2. 尚未取得成果之板塊顯示為淡色線稿拼圖（Ghost Piece），點擊後跳出提示：「專三前建議取得至少一張乙級或兩張丙級技術士證，點此查看推薦證照清單」。
  3. 點擊已點亮之拼圖塊，立即滑出「佐證檔案抽屜」，展示已綁定之附件與反思心得。

#### [US-04] 一鍵產生個人自傳與學習計畫 (Word 匯出)
- **As a** 面臨升學二技或就業實習之專五學生
- **I want to** 點擊「一鍵產生自傳」按鈕，系統結合我確認過的所有拼圖能力資料，產出自傳草稿與讀書計畫
- **So that** 我無須從零開始構思自傳框架，並可直接下載為標準 Word (`.docx`) 檔進行後續修訂。
- **驗收條件 (Acceptance Criteria)**：
  1. 系統自動聚合：修課優勢領域、證照亮點、專題實作成績、競賽成果與自我反思。
  2. 產出具備邏輯結構之自傳（個人背景與就讀動機、專業技能積累、專題專案經歷、未來目標展望）與學習/讀書計畫（近程、中程、遠程）。
  3. 介面提供 Markdown 線上編輯器，並提供「匯出 Word (.docx)」功能，版面排版符合學校標準格式。

### 2.2 例外情境處理矩陣 (Exception Scenarios)

| 代號 | 例外情境描述 | 觸發條件 | 系統處置機制與降級策略 (Graceful Degradation) |
| :--- | :--- | :--- | :--- |
| **EX-01** | 非資管科課程或跨校轉入科目 | 上傳之成績單包含本校課程清單未定義之科目名稱。 | 標記為「待科辦核准之自訂課程」，保留原始分數與學分，歸類於「其他/彈性學分」，不中斷後續自傳生成流程。 |
| **EX-02** | 影像嚴重模糊或文字顛倒無法辨識 | 掃描檔 DPI 過低、光線不足、傾斜超過 45 度。 | AI 回傳辨識信心度低於門檻（< 0.60），系統顯示警示：「無法清晰辨識該文件」，主動切換為「空白表單人工填寫模式」，允許手動填入後上傳附件。 |
| **EX-03** | 成績單標記未明 (如代碼特殊) | 出現非標準符號或特殊記號（非明確之抵/免/補）。 | 系統將該科目標記為「狀態待審核」，並於確認介面以黃色警示提示學生手動選取：【普通及格】、【抵免】、【免修】或【補修】。 |
| **EX-04** | 重複上傳相同文件 | 學生重複上傳相同證照或同一學期成績單。 | 系統進行 SHA-256 檔案雜湊比對；若重複，彈窗提示：「已存在相同檔案（上傳於 YYYY-MM-DD），是否覆蓋既有紀錄？」，由學生自主決策。 |
| **EX-05** | 第三方 API 故障或網路中斷 | Gemini API 服務異常、逾時 (Timeout) 或額度耗盡。 | 系統無縫降級 (Fallback) 至 `fake` 模式或本地規則解析器，自動生成空白待校正表單，並通知學生：「目前改以本機模式處理，請手動確認欄位」。 |
| **EX-06** | 學生撤回 AI 處理同意 | 學生在歷程設定中取消勾選第三方 AI 處理授權。 | 系統立即封鎖所有發往外部 API 的請求，既有未送出之暫存遮蔽資料立即銷毀，後續功能僅使用本機規則庫。 |

### 3.2 成熟校園插畫式互鎖拼圖 (Interlocking Campus Puzzle) 專屬規範

> [!CAUTION]
> **視覺紅線宣告**：拼圖是本系統的核心世界觀「把五年，拼成下一站」的靈魂象徵。**絕對禁止**以一般常見的「線性時間軸節點 (Timeline Nodes)」、「樹狀圖 (Tree Diagram)」或「Bootstrap 式卡片清單 (Card Grid)」便宜行事！必須是扎實的「實體互鎖拼圖 (Jigsaw Interlocking Pieces)」。

#### 1. 八大板塊拓撲互鎖幾何結構 (Interlocking Geometry)
拼圖由 8 塊具備榫卯凹凸（Tabs & Blanks）邊界的形狀互鎖而成，每一塊拼圖的邊緣皆與相鄰拼圖精確咬合，象徵學生的各項能力相互支撐、不可割裂：
1. **01. 課程與學業基底 (Base Curriculum)**：左上基石，向右凸、向下凸。
2. **02. 專題實作歷程 (Capstone Project)**：中上主幹，向左凹、向右凸、向下凹。
3. **03. 專業技能與證照 (Certificates)**：右上指標，向左凹、向下凸。
4. **04. 程式與作品成果 (Portfolio Works)**：中左樞紐，向上凹、向右凸、向下凹。
5. **05. 競賽與創新活動 (Competitions)**：中央核心，向上凹、向左凹、向右凸、向下凸。
6. **06. 業界實習與職場 (Internship)**：中右連結，向上凹、向左凹、向下凸。
7. **07. 個人反思與成長 (Reflection)**：左下收納，向上凹、向右凸。
8. **08. 下一站進路準備 (Next Station)**：右下錨點，向上凹、向左凹。

#### 2. 成熟校園插畫質地與色彩 (Campus Morandi Aesthetics)
- **整體氛圍**：70% 安靜耐看（避免霓虹炫光或低幼卡通感）+ 20% 雜誌書籍排版 + 10% 微互動。
- **色彩計畫**：
  - 基底底層：霧白 (`#F8FAFC`)、宣紙暖灰 (`#F1F5F9`)。
  - 拼圖本體：學院深藍 (`#1E293B`)、典雅石青 (`#334155`)、墨綠苔蘚 (`#1E3A2F`)。
  - 點綴強調：霧面冷金 (`#D97706`)、理性藍青 (`#0284C7`)。
  - 嚴格禁用：手遊螢光綠、刺眼警示紅、AI 紫粉漸層。
- **材質細節**：每塊拼圖表面採用 CSS SVG 噪點濾鏡 (Fine Paper Grain Texture)，呈現如高磅數紙卡印刷與手工雕琢之手感。

#### 3. 動態微互動與狀態規範 (Micro-Interactions)
- **已解鎖狀態 (Lit State)**：拼圖內部顯現細膩之手繪校園插畫（例如：圖書館拱窗、終端機代碼框、獎章雕紋），滑鼠懸停時產生微浮雕陰影 (`box-shadow: 0 10px 25px -5px rgba(30,41,59,0.15)`)，拼圖微微上浮 3px。
- **淡色空拼圖 (Ghost Blank State)**：尚未有資料之板塊，以細緻的虛線莫蘭迪灰呈現輪廓，中間浮水印式標記「待拼入」，絕不使用「紅色未及格」字眼，保持引導鼓勵性。
- **點擊行為 (Click-to-Drawer)**：點擊任一拼圖塊，絕不另開新分頁，而是平滑滑出該能力領域的「佐證檔案抽屜 (Evidence Drawer)」，列出所有關聯的成績科目、證照原件預覽與反思筆記。

### 4.1 抽象分析介面與 Provider 工廠設計
系統透過抽象介面隔離外部 AI 相依性，支援環境變數動態切換：

```python
class IDocumentAnalysisProvider(ABC):
    @abstractmethod
    def extract_transcript(self, anonymized_text: str) -> TranscriptDraftDTO:
        """從去識別化文字擷取科目、學分、成績與狀態"""
        pass

    @abstractmethod
    def extract_certificate(self, anonymized_text: str) -> CertificateDraftDTO:
        """從去識別化文字擷取證照名稱、級別與取得日期"""
        pass

    @abstractmethod
    def generate_autobiography(self, confirmed_profile: StudentProfileDTO) -> AutobiographyDTO:
        """結合已確認學生歷程產出自傳與讀書計畫"""
        pass
```

- **Fake Provider (`DOCUMENT_ANALYSIS_PROVIDER=fake`)**：
  - 現行系統預設。完全運行於本機內部，以擬真資料結構產出標準草稿，絕不向外部網路發送任何位元組，專門用於離線展示、單元測試與安全受限環境。
- **Gemini Provider (`DOCUMENT_ANALYSIS_PROVIDER=gemini`)**：
  - 僅於取得使用者每件檔案明確勾選授權同意後方可啟用。

### 4.2 本機資料去識別化 (PII Masking) 管道
在呼叫任何外部 API 之前，系統在後端伺服器記憶體中執行強制去識別化程序：
1. **影像遮蔽 (Image Redaction)**：若涉及 OCR，先於本機端辨識文字座標，對包含個人身份之區塊（如成績單抬頭之學生姓名、身分證號、家庭住址、學號）進行馬賽克塗黑。
2. **文字過濾 (Text Sanitization)**：
   - 姓名：轉換為 `[STUDENT_NAME]`
   - 身分證字號 / 居留證號：Regex 匹配 `[A-Z][1289]\d{8}`，轉換為 `[NATIONAL_ID]`
   - 學號：轉換為 `[STUDENT_ID]`
   - 出生日期 / 住址：轉換為 `[DATE_OF_BIRTH]` / `[ADDRESS]`
3. **最小傳輸原則 (Data Minimization)**：**嚴禁向外部傳送成績單或證照的原始整頁圖片與 PDF**，僅傳送經本機去識別化後的「課程成績清單純文字（Markdown Table）」或「證照條目文字」。

### 4.3 檔案安全暫存與硬刪除架構 (Secure Storage & Hard Delete)

> **2026-09-23 修正**：本節定義安全目標與可替換實作，不預先承諾目前 Flask 專案尚未具備的 JWT、`.enc` 檔案格式或 Celery。

1. **儲存隔離 (Isolation)**：
   - 測試版將原始檔存放於應用程式設定的私有儲存路徑，依不可猜測的使用者／文件識別碼隔離。
   - 禁止將檔案存放於靜態公開目錄 (Web Root)。
   - 靜態檔名、加密容器格式與日後雲端儲存由 Storage Adapter 負責；若尚未完成靜態加密，必須在部署檢查表明確標註，不得假稱已使用 `.enc`。
   - 存取以**現有 Flask 登入 Session**及伺服器端所有權檢查為基準，關聯不可變的內部 `user_id`；JWT 僅是未來可選替換方案。
2. **暫存生命週期 (TTL Policy)**：
   - 上傳辨識過程中的中介暫存檔（Scratch Files）安全目標為 24 小時 TTL；測試版以可測試的清理服務／管理指令執行，量產後才依負載替換為排程或背景佇列。
3. **物理硬刪除規範 (Hard Delete Protocol)**：
   - 當學生在主頁點擊「刪除檔案」時，系統執行不可逆的硬刪除：
     - 透過儲存介面物理刪除原始附件檔案。
     - 清除實際存在的對應文件、待確認草稿與 AI 快取關聯資料。
     - 清除快取中的 PII，稽核紀錄只保留不可還原的識別碼、時間與操作者。
