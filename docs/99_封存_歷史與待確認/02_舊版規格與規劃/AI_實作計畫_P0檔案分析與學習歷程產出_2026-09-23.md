## 架構與邊界

新增獨立的 `learning_profile` 模組，不改寫既有 `Portfolio` 送審流程：

```text
私有上傳檔
  → DocumentAnalysisProvider（Gemini／離線測試替身）
  → 可確認的 ExtractionResult
  → CourseRule 與 CredentialRecord
  → LearningProfileOutput
  → HTML 結果頁與 DOCX 匯出
```

- 正式外部 AI 服務僅透過伺服器端環境變數呼叫；禁止在 HTML、JavaScript、Git 或資料表寫入 API 金鑰。
- 資料不足、外部模型失敗或無法辨識時，必須保存失敗狀態與原始檔，要求學生人工補正；不得產生虛構的課程、成績、證照或錄取結論。
- 學號仍是顯示與登入欄位，歷程資料一律以 `User.id` 關聯；校內轉科不變更帳號，校外轉入由管理員建立新帳號。
- P0 只建立「待規則確認」的 `抵／免／補` 狀態；不判定正式抵免、補修資格或畢業資格。

## Task 1：建立 P0 資料模型與遷移

**目標：** 建立私有來源文件、可確認擷取、年度課程規則、證照紀錄與可版本化輸出的資料模型。

**介面：**

```python
class SourceDocument(db.Model):
    # owner_id, document_type, display_name, file_path, sha256, status

class DocumentExtraction(db.Model):
    # source_document_id, provider, status, result_json, error_message, confirmed_at

class CourseRule(db.Model):
    # school_year, course_name, normalized_course_name, category,
    # requirement_type, credits, is_active

class CredentialRecord(db.Model):
    # student_id, source_document_id, title, level, issued_on, issuer,
    # category, confirmation_status

class LearningProfileOutput(db.Model):
    # student_id, school_year, source_summary_json, summary_text,
    # autobiography_draft, study_plan_draft, generated_at, version_no
```

**步驟：**

1. 在 `tests/test_learning_profile_models.py` 建立資料庫 fixture，驗證所有 P0 模型都以 `User.id` 關聯，且 `CourseRule` 必須以 `school_year + normalized_course_name` 唯一。
2. 加入 `test_status_mark_is_not_a_numeric_score`：輸入 `抵`、`免`、`補` 時，模型保存文字狀態而非虛構數值成績；`補` 不能自動設為通過。
3. 執行 `pytest -q tests/test_learning_profile_models.py`，確認在模型尚未建立時失敗。
4. 在 `app/models/learning_profile.py` 實作模型與關聯，並於 `app/models/__init__.py` 匯出。
5. 建立 migration，加入外鍵、索引、唯一鍵與 `JSON` 欄位；不可變更既有 `portfolios` 表的資料語意。
6. 再執行 `pytest -q tests/test_learning_profile_models.py`，確認通過。

## Task 2：建立文件分析介面與安全上傳

**目標：** 讓 PDF／PNG／JPG 上傳後建立私有來源文件與可追溯的擷取任務；分析服務可在 Gemini 與測試替身間切換。

**介面：**

```python
class DocumentAnalysisProvider(Protocol):
    def analyze(self, *, path: Path, document_type: str) -> dict: ...

def create_analysis_provider(config: Mapping[str, Any]) -> DocumentAnalysisProvider: ...

def create_source_document(*, actor: User, upload: FileStorage,
                           document_type: Literal["transcript", "credential"]) -> SourceDocument: ...

def request_extraction(document: SourceDocument,
                       provider: DocumentAnalysisProvider) -> DocumentExtraction: ...
```

**步驟：**

1. 在 `tests/test_document_analysis.py` 寫測試：學生可上傳 PDF／PNG／JPG；不允許 `.exe`、路徑穿越、超出既有大小上限或存取他人文件。
2. 寫測試替身 `FakeDocumentAnalysisProvider`：只回傳前述 `DEMO_TRANSCRIPT`／`DEMO_CREDENTIAL` 的資料，不讀取真實檔案內容。
3. 寫失敗測試：未設定 `GEMINI_API_KEY`、供應者失敗、回傳缺少必要欄位時，建立 `failed` 擷取紀錄並保留原檔；不得建立課程或證照資料。
4. 在 `requirements.txt` 加入 `google-genai` 與 `python-docx`；在 `Config` 加入 `DOCUMENT_ANALYSIS_PROVIDER`（預設 `fake`）與僅伺服器讀取的 `GEMINI_API_KEY`。
5. 實作 `GeminiDocumentAnalysisProvider`，以嚴格 JSON schema 要求回傳 `courses` 或 `credential`，並將原始模型文字僅留在伺服器端任務紀錄；不將 API 金鑰傳至瀏覽器。
6. 實作安全上傳、SHA-256 計算、私有儲存與擷取任務；重用 `validate_upload_filename`，並將 P0 允許副檔名限縮為 `pdf,png,jpg,jpeg`。
7. 執行 `pytest -q tests/test_document_analysis.py`。

## Task 5：生成可編輯摘要、草稿與 Word 文件

**目標：** 只使用學生已確認的資料與有效課程規則生成內容；資料不足時顯示缺口。

**路由：**

```text
POST /student/learning-profile/generate
GET  /student/learning-profile/output/<output_id>
GET  /student/learning-profile/output/<output_id>/download.docx
```

**步驟：**

1. 在 `tests/test_learning_profile_flow.py` 寫生成測試：已確認課程與證照會出現在摘要；未確認資料、空白經歷與無規則課程不會被描述為已完成能力。
2. 寫資料不足測試：缺成績單、缺課程規則或缺證照時，回傳明確待補清單，不產生捏造的自傳段落。
3. 寫 DOCX 測試：下載回應為 Office Open XML MIME type，檔名為 `learning-profile-<output_id>.docx`，文件包含「學習歷程摘要」「自傳草稿」「學習／入學計畫草稿」三個標題。
4. 實作 `generate_learning_profile_output(student, school_year, provider)`；若使用 Gemini，只將已確認欄位與待補狀態送出，並要求 JSON 欄位 `summary_text`、`autobiography_draft`、`study_plan_draft`；沒有可用供應者時，使用可預測的規則式草稿。
5. 實作 `export_learning_profile_docx(output)`，以 `python-docx` 寫入來源說明、摘要、待補清單與兩份可編輯草稿；不嵌入原始人像、成績單或證照影像。
6. 執行 `pytest -q tests/test_learning_profile_flow.py`。
