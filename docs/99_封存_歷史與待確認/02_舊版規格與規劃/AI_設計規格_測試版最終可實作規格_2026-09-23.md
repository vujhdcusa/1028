# 資管科智慧學習歷程系統－測試版最終可實作規格

狀態：等待使用者最後確認（本文件確認前不進行架構重構）  
版本：2026-09-23  
決策基礎：`AI_設計規格_單一核心流程重整提案_2026-09-23.md`、首頁與拼圖視覺分鏡、檔案分析與學習歷程產出基準、使用者於 2026-09-23 的確認。

## 1. 測試版要交付的核心結果

學生在**同一個工作檯**完成：上傳私有資料 → AI／本機規則整理 → 本人校正確認 → 8 塊互鎖拼圖呈現能力證據 → 一鍵產生可編輯的自傳與學習計畫草稿 → 匯出 Word。

系統的價值是減少學生重打資料；AI 不是學籍、畢業資格、升學錄取或職涯建議的最終決定者。

## 2. 範圍邊界

### P0：本次必須可操作

- 一個學生主工作檯，清楚引導「上傳、確認、看見拼圖、產生自傳」四步，不以多頁分散流程取代。
- 上傳成績單、證照、競賽／活動、專題／作品等私有文件；每次交給 Gemini 前必須勾選同意。
- 本機擷取與規則判讀優先；Gemini 僅接收去識別化後的最小必要文字／結構資料，回傳可校正草稿。
- 學生可修正、刪除或補充辨識欄位，確認後才寫入正式學習歷程。
- **可用的 8 塊互鎖拼圖**：課程、作品、證照／技能、競賽／活動、專題、實習、反思、下一站。每塊必須可點擊，顯示已確認的佐證、完成／缺漏狀態與下一步引導；未完成以淡色空拼圖表示。不得用線性節點、進度條或卡片清單冒充拼圖。
- 一鍵產生可編輯的自傳及學習／讀書計畫草稿，並可匯出 `.docx`。
- 系統共用 API 與學生個人 API 金鑰兩種模式：單次貼上即丟棄，以及學生明確同意後的安全保存、使用、撤銷與替換。
- 公開資料來源登錄、年度差異偵測候選項、科辦覆核與發布狀態；學生只看見已發布內容或「科辦確認中」。

### P2：只做深化，不挪走 P0 功能

- 依首頁六幕分鏡加入成熟校園插畫、紙材紋理、佐證抽屜過場、手持拼圖等視覺敘事。
- 提供細緻但可關閉的動畫，尊重 `prefers-reduced-motion`。
- 視負載增加背景佇列、速率監控與更完整的公開來源擷取器。

P2 不得把拼圖幾何本體、拼圖互動或學生主流程延後。

## 3. 單一學生工作檯流程

1. **開始與同意**：學生選擇文件類型與分析方式（本機規則／Gemini），閱讀本次外送的資料範圍並勾選同意。
2. **私有上傳**：文件進入非公開儲存；系統檢查格式、大小、重複檔與可辨識性。
3. **本機處理優先**：擷取文字、遮蔽姓名、身分證、學號、電話、地址等個資；建立最小必要結構資料。原始文件不得傳至 Gemini。
4. **草稿解析**：Fake Provider 可供展示與測試；Gemini 成功時回傳候選結構。逾時、額度不足或結果不可靠時，保留本機規則結果並轉人工校正。
5. **學生確認**：學生校正科目、成績、抵／免／補、證照名稱／類別、競賽與作品描述。只有按下確認的內容會成為正式資料。
6. **拼圖映射**：已確認證據連結至 8 塊互鎖拼圖；點擊拼圖可查看來源、人工確認時間與可補強事項。
7. **一鍵產生**：以確認後資料產生自傳／計畫草稿。學生可編輯、重產生與匯出；文稿需標示 AI 輔助草稿而非校方正式證明。

引導文字採陪伴式且不替學生下結論，例如：「這裡還是空的，先放一段最近完成的作品吧。」、「已經幫你留下來了。」與「幫你看了一下，這裡可能還能再補強。」

## 4. AI、個資與 API 金鑰

### 4.1 資料最小化與人工把關

- 每一次外部 Gemini 分析各自記錄同意時間、文件類型、遮罩版本與目的；撤回同意後停止後續外送並依刪除流程清除可刪除資料。
- Gemini 免費方案的條款與額度屬部署前必查事項；測試版預設不傳敏感個資、原始圖片或整份 PDF。
- 本機規則與學生確認永遠可用，且優先於 AI 的推測；抵、免、補與畢業／抵免判定顯示為「待科辦規則或人工確認」，不可由模型直接定案。

### 4.2 金鑰模式

| 模式 | 行為 | 必要保護 |
| --- | --- | --- |
| 系統共用 | 管理端設定伺服器端金鑰，為使用者提供額度 | 不回傳前端、不寫入日誌或 Git；顯示可理解的額度／失敗提示 |
| 個人單次 | 學生本次手動貼上，用完立即從記憶體／Session 清除 | 不落資料庫、不顯示完整值 |
| 個人保存 | 學生另行勾選同意後保存供未來使用 | 伺服器端加密／金鑰管理、只顯示末四碼、可撤銷與替換；主密鑰只存在部署環境 |

## 5. 公開資料年度更新模組

資料來源登錄表先收錄二技招生公開資料與康寧大學資管科公開頁面（例如 `https://www.techadmi.edu.tw/`、`https://im.ukn.edu.tw/`）。

1. 擷取器產生候選變更與來源快照／日期。
2. 系統比對去年已發布版本，標示新增、移除與內容改動。
3. 科辦人員審閱、補充說明並明確發布。
4. 僅已發布資訊可影響學生的「下一站」提示；未覆核資料只顯示「偵測到新資料，科辦確認中」。

不承諾自動錄取判斷、不寫入外部網站，也不把網頁抓取結果視為校方最終規定。

## 6. 與目前 Flask 專案相容的實作邊界

- 身分驗證沿用現有 Flask Session；每個服務入口必須做伺服器端所有權檢查。JWT 可在未來換用，非本次條件。
- 用 Storage Adapter 實現私有檔案儲存與刪除。測試版可使用設定的私有本機路徑；是否啟用靜態加密、加密容器或雲端儲存必須由部署設定與檢查表如實揭露。
- 非同步工作採可替換介面：測試版使用既有 Flask 可承擔的受限重試／管理清理操作；日後依負載選擇排程或佇列。Celery 不是既定依賴。
- 文件分析透過 Provider 介面切換 `fake` 與 `gemini`，避免讓路由層直接依賴外部 API。
- 不把原始文件或 API 金鑰寫進測試資料、開發日誌、版本控制或前端 HTML。

## 7. 最小驗收準則

- 未勾選本次同意者，不能送 Gemini；同意後仍必須只送去識別化結構資料。
- Gemini 失敗、429 或解析不完整時，學生仍能以本機規則與人工表單完成確認。
- 8 塊拼圖可操作、具有實際互鎖外觀，並能連至已確認佐證與空缺引導。
- 使用者不得讀取其他學生的原始文件、草稿、已保存個人金鑰或拼圖佐證。
- 刪除／撤回流程會清除私有檔、對應草稿與 AI 快取，且稽核紀錄不含可還原個資。
- 公開資料未經科辦發布時，不會以事實或升學建議呈現在學生端。
- 自傳 Word 匯出含已確認資料，並允許學生先編輯草稿。
