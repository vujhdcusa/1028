> **2026-09-29 狀態修正：** 此計畫中的教師／行政審查與版本流程只保留為既有支援功能，不再是現行 P1 主計畫。先完成 [P0 檔案分析需求基準](./AI_需求基準_檔案分析與學習歷程產出_2026-09-23.md)，再依[行政表單數位化與申請追蹤實作計畫](./AI_實作計畫_行政表單數位化與申請追蹤_2026-09-29.md)開發 P1；不得直接把本文件剩餘任務當成下一步。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成角色統一、專題模板、學生提交、教師／行政審查與安全的 AI 初檢骨架。

**Architecture:** 以 Flask blueprint、SQLAlchemy model 與 service layer 分離角色路由、資料所有權、提交版本及審查狀態。保留現有 `Portfolio` 與 `AgentTask`，以新增模型承接模板、快照、版本、分派與共同結論；所有 AI 輸出停留在分析紀錄，不修改正式結論。

**Tech Stack:** Python 3.11+, Flask 3.0, Flask-SQLAlchemy, SQLite in-memory tests, MySQL/MariaDB runtime, pytest.

**Spec:** `AI_設計規格_學習歷程核心流程_2026-09-21.md`

## Global Constraints

- 正式登入角色只允許 `student`、`teacher`、`staff`、`admin`。
- `reviewer` 不得再導頁或通過角色檢查。
- 學生、教師、staff 的資料存取都必須在後端重新檢查授權。
- 提交快照與歷史版本不可被後續模板或新版本覆蓋。
- AI 不可自動產生正式通過、退回或補件結論。
- 每個功能先寫 failing test，再寫 production code。
