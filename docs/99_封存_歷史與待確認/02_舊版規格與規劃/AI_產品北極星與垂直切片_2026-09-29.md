# AI 產品北極星與垂直切片

> 版本：2026-09-29（教師／行政需求修正版）
> 用途：作為三人開發與個人整合線共同遵守的產品標準。
>
> **2026-10-06 調整：** 依指導老師意見，主線改為「選擇目標校系 → 收齊六類學習資料 → 比對缺件 → 導師確認 → 產出完整備審資料」；下方第三節「行政表單 P1」改列為後續擴充。詳見 [指導老師討論紀錄與主線收斂](AI_會議紀錄_指導老師討論與主線收斂_2026-10-06.md) 與正式規格書。

## 一、北極星問題

學生能否把真實但去識別化的成績、證照及行政申請資料放入系統，在可追溯、可校正、不捏造的前提下，取得可使用的學習歷程文件，並完成需要教師初檢與科辦追蹤的表單申請？

系統必須同時證明兩種價值：

1. 學生不必在資料分散時重新整理全部學習證據。
2. 教師與科助不必靠紙本、Email 或人工表格逐筆追查誰未交、缺什麼及使用哪個版本。

原本的教師學習歷程回饋可以保留，但不再是教師端唯一需求或主要展示論據。

## 二、第一條垂直切片：學生學習歷程 P0

```text
學生登入
→ 上傳成績單／證照
→ 系統建立非空的擷取草稿
→ 學生修改並確認
→ 套用適用年度課程與證照規則
→ 顯示摘要、缺漏、待確認項目
→ 產生自傳／學習計畫草稿
→ 下載 Word
```

## 三、第二條垂直切片：行政表單 P1

```text
教師發布有年度與截止日的表單版本
→ 學生下載並離線填寫
→ 學生回傳表單與必要佐證
→ 系統／AI 產生缺件候選提示
→ 教師初檢並要求補件或轉交
→ 科辦查看跨班進度並登錄正式行政結果
→ 學生查看狀態與補件原因
```

AI 關閉或失敗時，規則檢查與人工流程仍須可完成。

## 四、不可降低的標準

- 不以貼 JSON 或手動重打全部資料作為唯一展示方式。
- 每個正式欄位都能追溯到來源檔、表單版本、規則版本或人工確認紀錄。
- 發布後的表單版本不可覆寫；學生提交必須指向實際下載版本。
- AI 只能產生草稿、缺漏、空白或版本疑義提示；不可直接形成正式結論。
- `抵／免／補` 不可當成固定分數；正式資格仍須人工及正式程序確認。
- 解析失敗時保留原始檔、顯示可理解錯誤，並提供人工處理入口。
- 一般檔案分享、一般作業繳交不算新核心；必須展示年度、指定對象、缺件、補件、狀態與稽核。
- 「測試通過」不等於「功能完成」；必須有可操作畫面與端到端驗收證據。

## 五、階段邊界

| 階段 | 內容 | 完成條件 |
|---|---|---|
| P0 | 成績單／證照輸入、學生確認、規則分類、摘要、草稿、Word | 匿名資料可完整走完第一條垂直切片 |
| P1 | 教師發布行政表單、學生電子回傳、缺件／補件、科辦進度與正式狀態；既有教師回饋為支援功能 | 匿名資料可完整走完第二條垂直切片，AI 失敗不阻塞 |
| P2 | 8 塊拼圖、五年地圖、公開首頁、動畫 | 只呈現已確認的 P0／P1 真實資料 |
| Future | 正式校務介接、進階推薦、完整自動 OCR | 需額外授權、規則與安全驗證 |

## 六、完成定義

功能只有同時具備「程式、測試、畫面、錯誤處理、來源／版本追蹤、權限與日誌」才可標示完成。規格草稿、空的 fake provider、只有檔案上下載或只有模型測試，不可標示為完成。
