# 雙專案與分支整合策略

> 版本：2026-09-29

## 一、兩條線

### A. 團隊協作線

- 用於組員 A、組員 B 開發與測試。
- 只接受契約明確、測試通過的功能。
- 允許失敗、回退與重做，不影響個人完整版本。

### B. 個人完整線

- 由你保留完整系統願景與可展示基準。
- 不直接讓組員在此線開發。
- 每次整合前先建立可回復快照。
- 組員功能以通過檢查的 commit 或 patch 形式帶入。

## 二、建議目錄

```text
D:\democase\ai                 個人完整線／整合基準
D:\democase\ai-team            三人協作線
D:\democase\ai-snapshots       整合前快照與可回復備份
```

實際建立前要先確認目錄不存在，避免覆寫既有專案。若 Git 工作區仍有未提交變更，先做檔案快照與清單，再建立基準 commit；不得用 reset 或 checkout 清除現有工作。

## 三、整合安全規則

- 組員不得直接推送到個人完整線。
- 一次只整合一位組員的一個功能。
- 整合前執行功能測試、完整測試、資料庫 migration 檢查與手動展示。
- 整合失敗時只移除該次候選變更，保留個人完整線與上一個整合快照。
- 不在沒有備份的情況下執行 migration、搬移使用者資料或修改共用資料庫。
