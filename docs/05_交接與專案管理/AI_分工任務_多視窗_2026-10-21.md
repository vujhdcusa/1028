# 多視窗分工任務（2026-10-21）

建立者：Claude（主視窗）
用途：使用者要同時開多個對話視窗分擔工作。每個任務一個視窗、一個 git worktree、一條分支，檔案範圍不重疊；每個視窗都要寫開發日誌、交接文件與工作佇列回報。

## 開工前狀態

- 基準分支：`feat/google-docs-autobiography`（已推到個人與小組 GitHub repo，`main` 都沒動）。
- 完整測試：見開發日誌最上面一節。
- 共用資料夾 `D:\democase\ai-wt-story` 是主視窗在用的；**其他視窗不要在這裡改檔或切分支**，一律開自己的 worktree。
- `docs/05_交接與專案管理/handoff.md` 有其他人未提交的修改，任何視窗都不要提交它。

## 所有視窗共同規則（每個開場指令都已包含）

1. 先讀 `D:\democase\AGENTS.md`、`D:\democase\ai\AGENTS.md`，全程正體中文。
2. 開自己的 worktree：`git -C D:\democase\ai worktree add D:\democase\_worktrees\<資料夾> -b <分支> feat/google-docs-autobiography`，之後只在那個資料夾工作。
3. 先寫測試、看它失敗，再實作；跑完整測試並如實回報最後一行。
4. 只用合成資料；`D:\democase\ai\docs\OCR測試資料\` 的真實檔案只能在本機讀，不能複製進 repo、測試或日誌。
5. **日誌**：在自己分支的 `docs/03_開發紀錄/development-log.md` 最上面加一節（日期、開發者、目標、修改檔案、驗證結果、下一步）。
6. **交接**：在自己分支新增 `docs/05_交接與專案管理/交接_<任務代號>_2026-10-21.md`，寫做了什麼、沒做什麼、怎麼驗證、下一個人從哪接；並在本文件對應任務打勾、填分支與提交。
7. **工作佇列**：在 `D:\democase\ai\docs\AI_代理協作_工作佇列.md` 最下方「代理回報」追加一筆（角色、日期、修改檔案、驗證方式、結果、風險／阻塞、下一步）。只追加，不覆寫別人的紀錄。
8. 只提交自己的檔案（不要 `git add -A`），不推送、不合併 main；要推送先問使用者推到哪裡。

- 狀態：[x] 完成（上傳後先到「辨識中」頁，背景辨識完成自動進確認頁；見 `交接_任務B_2026-10-21.md`）　分支：`feat/ocr-background-queue`　資料夾：`D:\democase\_worktrees\ai-wt-ocr-queue`
