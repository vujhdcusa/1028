## 一、期中開發目標

本階段不是把完整五年系統全部做完，而是完成一條能證明核心價值的流程：

```text
學生登入 → 建立成果 → 選擇目標 → 提交證據 → 保存目標快照
→ AI 初步比對 → 被分派教師查看 → 教師逐項覆核
→ 通過／退回／補件 → 學生提交 V2 → 保留完整歷程
```

期中交件另外要求概述、分工進度、資料字典、Repository 更新紀錄與每位組員 GitHub 活動紀錄；這些交件準備與系統功能同步進行，但不能以文件描述取代程式與資料庫證據。

## 四、下一階段開發順序

### 階段 3：學生成果提交與目標快照

**目標**：讓學生能建立一筆成果，選擇目標，填寫主張與說明，附加證據並提交。

**必要規則**：

- 只有本人能新增、編輯與提交自己的成果。
- 提交時將目標名稱、內容、版本或要求條件複製至 `submission_goal_snapshots`。
- 管理員日後修改目標，不得改變既有提交的快照。
- 附件不使用可猜測的公開網址，下載時必須重新檢查使用者授權。

**完成證據**：資料庫紀錄、學生表單、本人／他人權限測試、快照不受目標修改影響的測試。

### 階段 4：AI 初步證據比對

**目標**：先完成一種可展示的規則式或服務層 AI 初檢流程，讓 AI 結果可被教師覆核。

**必要規則**：

- 每次執行建立獨立 `ai_analysis_runs` 紀錄。
- 狀態至少包含 `pending`、`running`、`succeeded`、`failed`。
- AI 找不到證據時只能顯示「未找到足夠證據」或「需要人工確認」，不可推論造假。
- AI 失敗時保存錯誤狀態與可理解訊息，不產生有效通過結論。
- AI 不得直接修改正式教師結論或提交狀態。

**完成證據**：成功執行、失敗執行、欄位不足與附件無法讀取的測試資料及畫面。

### 階段 5：教師分派與逐項覆核

**目標**：讓指定教師看見待審提交，逐項記錄人工判定並留下正式意見。

**必要規則**：

- 教師只能看被分派或明確授權的學生。
- 每筆教師覆核要指向特定提交版本與特定 AI 執行紀錄。
- 逐項結果至少包含符合、部分符合、不符合、需補件與理由。
- 正式結論由教師產生，不由 AI 自動通過。

**完成證據**：教師待審清單、未授權拒絕測試、逐項覆核紀錄、正式結論與意見畫面。

### 階段 6：V2 補件與歷程

**目標**：教師要求補件後，學生可依意見建立新版本，且歷史內容不可被覆蓋。

**必要規則**：

- V2 是新的 `portfolio_submissions` 紀錄，透過前一版本 ID 連結 V1。
- V1 的內容、目標快照、附件、AI 執行與教師覆核不可被 V2 改寫。
- V2 可重新產生新的 AI 執行紀錄與教師覆核紀錄。
- 查詢頁面必須能依時間看到版本、AI 執行人／時間、教師與結論。

**完成證據**：V1／V2 資料庫查詢、版本頁面、歷史不可變測試、端到端展示錄影或截圖。
