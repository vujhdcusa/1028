## 一、老師這次最重要的一句話

老師的擔心：

## 二、老師已經明確表達的決定

| # | 主題 | 老師的意思 |
| --- | --- | --- |
| 1 | 系統目的 | 這是**學生的學習歷程系統**，對象是學生，目標是協助學生把資料收齊，最後產出一份完整的**備審資料**，印出來就完成。 |
| 2 | 開發順序 | 先完成主線流程與主要功能，再加其他東西。不要一直擴充再收斂。 |
| 3 | 資料來源 | **不可以**用學生帳號登入學校系統去爬資料，會有資安問題。改為：**學生自己登入學校系統、下載資料，再上傳到本系統**。老師認可這個做法，但要求「要實際試過」。 |
| 4 | 學生要收的資料 | 各年成績（學分夠不夠）、歷年證照、歷年活動、競賽、服務學習等，約六類（見「待確認 C」）。資料由學生自己找、自己上傳。 |
| 5 | 目標校系 | 要**調查各校系要的備審內容與採計標準**（例如中科大某科系），放進系統。學生勾選要申請的校系後，系統告訴學生「你還缺什麼」。 |
| 6 | 最終產出 | 條件都滿足後，產出完整備審資料，學生印出來即可。 |
| 7 | 老師（導師）角色 | 幫學生看、確認內容是否合理、是否 OK。教師端功能比較少是正常的，先做出來再加。 |
| 8 | 教師端可加的功能 | 班級統計表，例如：本班學生要申請哪些學校。 |
| 9 | AI | 可以加在中間（例如幫忙辨識上傳的文件），但不是主軸。 |
| 10 | 科助與系統管理員 | 是兩件不同的事。**系統管理員是你們（開發者）**，不是科助。 |
| 11 | 範圍 | 先做「科」的，不做全校。 |
| 12 | 科助表單、證照獎勵單、學習地圖 | 屬於副本／後續。老師提到學校現有的證照系統已經在處理證照相關業務，質疑為什麼要在本系統重做。 |

## 三、老師交代、還沒有答案的事（回家作業）

| 代號 | 問題 | 要怎麼做 |
| --- | --- | --- |
| A | **科助在系統裡到底要做什麼？為什麼需要科助？** | 先寫清楚科助的任務；說不出必要性就先不做科助端。 |
| B | **備審資料現在是誰在收、誰在看？**（科辦還是導師） | 老師要求「要去問，不是聽說」。實際去問科辦或導師，記錄對方姓名與日期。 |
| C | **學生要收的「六類資料」是哪六類？** | 錄音只辨識出：成績與學分、證照、活動、競賽、服務學習；第六類疑似「幹部」或「出缺勤」，請組員確認。 |
| D | **學校成績系統的限制要怎麼克服？** | 學校系統只顯示期末成績；期中修畢的課（例如部分選修）在系統上會消失，只有列印成績單才完整；微學分課程不會印在成績單上。需要想辦法處理，例如以列印版成績單為準、微學分另外上傳證明。 |
| E | **各校系備審要求調查** | 已有資料：`school/Documents/116二技技優甄審_時程與備審加權_修訂版.pdf` 整理了 115 學年度 83 個志願的備審加權。資管相關四個志願已整理成[種子資料](../02_需求與設計/04_原始資料與參考/AI_種子資料_二技技優資管相關校系備審加權_115.csv)；剩下要確認的是各項目對應到哪些資料類別（標「待確認」者）。 |
| F | **主線流程圖** | 老師的首要要求。先畫出學生從登入到產出備審資料的完整流程。 |

## 四、使用者角色（目前討論結果）

| 角色 | 狀態 | 說明 |
| --- | --- | --- |
| 學生 | 確定 | 主要使用者 |
| 導師 | 確定 | 看本班學生資料、確認內容、看班級統計 |
| 專任教師 | 討論中 | 教該門課的老師，可能需要知道學生的作品；先歸在教師端 |
| 科助 | **未定** | 必須先回答作業 A |
| 系統管理員 | 確定 | 開發者本人，負責維護校系條件、帳號等資料 |

## 五、主線流程（依老師意見整理，待組員確認）

```text
學生登入
→ 選擇想申請的二技校系
→ 系統顯示該校系需要的備審資料與標準
→ 學生自行登入學校系統，下載成績單等資料
→ 學生把六類資料上傳到本系統（AI 可協助辨識）
→ 學生確認系統整理出的內容
→ 系統顯示「還缺什麼」
→ 導師查看並確認內容合理
→ 系統產出完整備審資料，學生下載列印
```

## 六、與目前規格書（2026-09-29 版）的衝突

| 目前規格書的寫法 | 老師這次的意見 | 建議 |
| --- | --- | --- |
| 「行政表單數位化與申請追蹤」列為 P1、第二條主線，教師端與科助端以表單為主 | 核心是學生；科助表單屬於副本；學校證照系統已在處理 | 行政表單從 P1 移到「後續擴充」 |
| 目標校系、各校系備審要求放在延伸功能 | 是主線的一部分：選校系 → 告訴學生缺什麼 | 選校系與缺件比對移入主線 |
| 教師角色只有一種 `teacher` | 區分導師與專任教師 | 先保留一種 `teacher`，用「負責班級」區分；專任教師待定 |
| 科辦／行政 `staff` 是正式角色 | 科助任務未定，必須先說明必要性 | 標為「待確認」，完成作業 A 再決定 |
| 最終產出是 Word 自傳／學習計畫草稿 | 最終產出是「完整備審資料」 | 產出目標改為完整備審資料（可列印） |
| 學習地圖、拼圖動畫等視覺功能 | 先不要想那麼多 | 列為後續美化 |

## 七、建議的兩週行動

1. **第 1～3 天**：組內確認本紀錄；完成作業 B（去問備審資料由誰收）與作業 C（確認六類資料）。
2. **第 3～5 天**：畫出主線流程圖（作業 F），拿給老師確認。
3. **第 1 週內**：完成作業 E，整理 3～5 個目標校系的備審要求。
4. **第 2 週**：依確認後的流程修改規格書，開始做第一個能操作的畫面：登入 → 選校系 → 上傳成績單 → 顯示缺件清單。
5. **作業 A（科助）與作業 D（成績系統限制）**：在下次見老師前準備好答案或處理方案。
