# AI 產品北極星與垂直切片

> 版本：2026-09-29
> 用途：作為三人開發與個人整合線共同遵守的產品標準。

## 一、北極星問題

學生能否把一份真實、匿名的成績單與證照資料放入系統，在可追溯、可校正、不捏造的前提下，取得可以直接編輯與下載的學習歷程文件？

所有功能先回答這個問題。不能直接幫助「輸入資料 → 學生確認 → 規則整理 → 可用產出」的功能，暫不阻塞第一個可展示版本。

## 二、第一條垂直切片

```text
學生登入
→ 上傳成績單／證照
→ 系統建立非空的擷取草稿
→ 學生修改並確認
→ 套用適用年度課程與證照規則
→ 顯示摘要、缺漏、待確認項目
→ 產生自傳／學習計畫草稿
→ 下載 Word
```

## 三、不可降低的標準

- 不以貼 JSON 或手動重打全部資料作為唯一展示方式。
- 每個正式欄位都要能追溯到來源檔、規則版本或學生確認紀錄。
- AI 只能產生草稿、缺漏提示或候選問題；不可直接形成正式結論。
- `抵／免／補` 不可當成固定分數；正式資格仍須人工或年度規則確認。
- 解析失敗時要保留原始檔、顯示可理解錯誤，並提供人工校正入口。
- 「測試通過」不等於「功能完成」；必須有可操作畫面與端到端驗收證據。

## 四、階段邊界

| 階段 | 內容 | 完成條件 |
|---|---|---|
| P0 | 成績單／證照輸入、學生確認、規則分類、摘要、草稿、Word | 匿名資料可完整走完垂直切片 |
| P1 | GitHub／README／佐證 AI 初檢、教師回饋、科辦正式結論、補件版本 | AI 報告與人工責任可回查 |
| P2 | 8 塊拼圖、五年地圖、公開首頁、動畫 | 只呈現已確認的 P0／P1 真實資料 |
| Future | 正式校務介接、進階推薦、完整自動 OCR | 需額外授權、規則與安全驗證 |

## 五、完成定義

功能只有同時具備「程式、測試、畫面、錯誤處理、來源追蹤、日誌」才可標示完成。規格草稿、空的 fake provider 或只有模型測試，不可標示為完成。
