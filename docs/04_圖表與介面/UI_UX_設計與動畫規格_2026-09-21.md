## 1. 設計結論

本系統不採用一般「登入後四張統計卡片加左側欄」的制式 Dashboard，也不將所有頁面都做成藝術展示。整體採用兩種互補的介面層：

- `Experience Layer`（體驗層）：公開首頁、學生首頁、五年歷程與個人作品集。這一層允許較強的動畫、路徑、節點、拼圖、重疊卡片與資訊編排，目標是讓使用者感覺學習歷程正在長大。
- `Work Layer`（工作層）：教師、科辦／行政、審查與資料維護頁。這一層以搜尋、篩選、表格、狀態、批次操作與清楚回饋為主，保留品牌色與節點語言，但不讓動畫妨礙工作。

### 1.1 系統母題

> **把五年，拼成下一站。**

### 1.2 視覺語言

| 視覺元素 | 系統意義 | 使用位置 |
|---|---|---|
| 拼圖 `Piece` | 一件作品、證照、課程、活動或專題成果 | 學生首頁、作品集、缺漏提醒 |
| 路徑 `Path` | 專一至專五的累積與成長 | 公開首頁、學生五年歷程 |
| 節點 `Node` | 一個里程碑、重要事件或下一步 | 首頁、進度、審查與行政摘要 |
| 檔案 `Archive` | 資料被保存、整理並重新使用 | 作品卡、證據、版本與審查頁 |
| 連線 `Connection` | 成果與目標、要求或下一站的關聯 | 目標頁、AI 建議、路徑圖 |

## 2. 資訊密度與版面原則

最新版本不再以大量空白作為主要風格，而是採「有呼吸感的資訊密度」：

```text
55% 文字與內容層級
25% 路徑、節點、卡片與圖像
15% 受控不對稱與重疊編排
 5% 微互動與裝飾動畫
```

### 2.1 受控不對稱

不追求每個區塊完全等寬、每句文案同長或所有卡片對齊，但也不允許隨機破壞可讀性。可採用：

- 12 欄格線中的 `7/5`、`8/4` 或 `5/7` 欄寬。
- 大、中、小三種卡片尺寸。
- 一張卡片跨兩欄，其餘卡片以單欄堆疊。
- 圖片、標籤、路徑線與文字有輕微重疊。
- 同一區塊混用短標籤、長說明、小註解與數值。
- 不強迫列表每一項的字數完全相同。

### 2.2 內容密度最低要求

每一個主要頁面至少應有：

1. 一個清楚、帶情境的主標題。
2. 一段解釋這個頁面要幫使用者完成什麼的說明。
3. 一個主要行動按鈕。
4. 一組狀態或進度資訊。
5. 一個可繼續探索或完成下一步的內容區塊。

## 3. 視覺設計 Token

### 3.1 色彩

```css
:root {
  --color-paper: #F5F2EC;
  --color-surface: #FFFFFF;
  --color-surface-muted: #EEEBE5;
  --color-ink: #20252B;
  --color-muted: #6E747B;
  --color-line: #D9D6CF;

  --color-cobalt: #4267D5;
  --color-teal: #2FAFA8;
  --color-yellow: #F2B84B;
  --color-coral: #E47B6C;
  --color-deep: #26354A;
}
```

用途規則：

- 紙張米白作為公開首頁與學生體驗層背景。
- 白色表面用於資料卡與工作層內容區。
- 鈷藍表示主要操作、目前階段與可點擊路徑。
- 青綠表示已完成、已保存或通過基本檢查。
- 黃色表示下一步、提醒或待處理，但不代表錯誤。
- 珊瑚色表示需要注意的資料，不以紅色大量製造壓力。
- 深藍黑只用於重要節點、深色卡片或高對比區塊。
- 不使用大面積 AI 紫色漸層，不讓色彩取代資訊層級。

### 3.2 字體與字級

- 中文首選 `Noto Sans TC`，備援 `Microsoft JhengHei`、`sans-serif`。
- 英文與數字首選 `Inter`，備援 `Arial`、`sans-serif`。
- 公開首頁主標題：`clamp(2.75rem, 7vw, 6.5rem)`，短句分行但不切斷語意。
- 頁面標題：`clamp(1.75rem, 3vw, 2.75rem)`。
- 卡片標題：`1.05rem` 至 `1.35rem`。
- 內文：`1rem`，行高 `1.7`。
- 註解與標籤：`0.75rem` 至 `0.875rem`。
- 避免整頁使用超細字重；重要文字至少 `font-weight: 600`。

### 3.3 間距與容器

- 基礎間距單位：`8px`。
- 桌機主要內容最大寬度：`1200px`。
- 公開首頁可放寬至 `1280px`，讓資料卡與路徑有空間交錯。
- 桌機頁面內距：`32px`。
- 平板頁面內距：`24px`。
- 手機頁面內距：`16px`。
- 一般卡片圓角：`12px`。
- 特殊展示卡片圓角：`20px`，每個區塊不超過兩張。
- 一般按鈕圓角：`8px`。
- 工作層側邊欄：`240px`；內容區最大寬度 `1200px`。

## 4. 文案與人味規則

所有介面文案採台灣常見網路服務口語，避免機器翻譯、官方公文或中國用語。

### 4.1 文案規則

- 使用「上傳、補件、查看、儲存、下一步、作品、資料」等台灣常用詞。
- 避免「信息、点击、提交附件、优化、完成度提升」等不自然用語。
- 句子長短可以不同，不讓所有卡片標題與說明看起來像同一個模板。
- 口語化要成熟，不使用大量 emoji、不做遊戲化分數、不假裝 AI 有情緒。
- 錯誤訊息要說明如何處理，不只顯示錯誤代碼。
- AI 建議要是低存在感的輔助入口，不搶走學生的主體性。

### 4.2 文案範例

| 生硬寫法 | 建議寫法 |
|---|---|
| 目前尚未建立任何學習成果資料。 | 這裡還是空的，先放一段你最近完成的作品吧。 |
| 資料提交成功。 | 已經幫你留下來了。 |
| 檢測到缺少必要文件。 | 還差一份資料，補上之後這一段就完整了。 |
| AI 分析結果 | 幫你看了一下，這裡可能還能再補強。 |
| 請選擇下一步操作。 | 接下來想先補哪一塊？ |
| 無資料 | 目前還沒有內容，完成第一筆後會顯示在這裡。 |

## 5. 頁面排版規格

### 5.1 公開首頁 `/`

公開首頁是展示級畫面，負責讓訪客理解資管科五年學習路徑，不先用傳統功能清單打招呼。

```text
Header：KUIM／資管科品牌、五年規劃、系統說明、登入

Hero：左側主標與說明；右側資料卡、節點、連線與小型標籤
Section 2：散落的成果如何被整理成五年路徑
Section 3：專一 → 專二 → 專三 → 專四 → 專五的成長路線
Section 4：升學／實習／就業三條下一站分岔
Section 5：系統如何協助留下、整理、連接與補足
CTA：開始整理自己的五年
```

Hero 不只顯示一句大標，至少要有一段 2～4 行說明、兩個行動入口、3～5 張資料卡與一組節點標籤。

### 5.2 學生首頁 `/student/dashboard`

學生首頁使用公開首頁的視覺語言，但資料改成個人化內容：

```text
上方：目前年級、姓名、保存狀態、通知
左側／上方：我的五年路線與目前節點
中央：成果拼圖、作品卡、證照、活動與專題
右側：還可以補上的地方、下一步建議、AI 低存在感入口
下方：最近更新、作品清單、版本與提交狀態
```

主要訊息要讓學生快速知道：

- 我現在走到哪裡？
- 我已經留下什麼？
- 還缺少哪幾塊？
- 下一步可以先做什麼？

### 5.3 作品集與成果編輯

- 列表頁使用不同寬度的作品卡，不做所有卡片同高同文案長度。
- 卡片必須顯示類型、年份、狀態、最後更新時間與主要證據。
- 編輯頁使用兩欄：左側表單，右側即時預覽／要求快照。
- 提交前以「你即將留下這個版本」說明不可逆或版本化行為。
- 成功後卡片滑入對應年份節點，而不是只顯示綠色 Toast。

### 5.4 教師工作台

- 左側固定導覽：班級總覽、待輔導、待審提交、通知與報表。
- 上方提供搜尋、班級、狀態、年級與風險篩選。
- 中央用列表或表格呈現學生；每列包含姓名、五年縮圖、缺件數、最近更新與狀態。
- 點擊學生後開啟右側抽屜或詳情頁，先顯示縮小版五年路線，再顯示表格資料。
- 批次通知、輔導建議與面談追蹤固定在可見操作區。

### 5.5 科辦／行政與審查頁

- 行政首頁可保留簡化節點網路作為品牌識別，但資料維護一定使用表格、搜尋、篩選與表單。
- 審查頁採雙欄：左側學生資料／證據／版本，右側要求項目／AI 候選提示／正式覆核。
- 審查狀態、補件、退回、通過與共同結論都必須有清楚文字，不靠顏色單獨表達。
- 表單送出、刪除、退回等高風險操作不使用大型動畫，改用明確確認與結果訊息。

## 6. 動畫與互動規格

### 6.1 動畫分級

| 區域 | 動畫程度 | 主要動畫 |
|---|---:|---|
| 公開首頁 | 高 | 資料漂浮、連線、Scroll 路徑、節點亮起、拼圖組合 |
| 學生首頁 | 中高 | 個人路徑繪製、成果卡進場、補件拼圖、AI 建議滑入 |
| 五年歷程 | 高 | 年份節點、成果聚合、目標分岔、資料聚焦 |
| 個人作品集 | 中 | 卡片上浮、路徑連線、狀態轉換 |
| 教師工作台 | 低 | 列表淡入、抽屜滑入、狀態更新 |
| 行政後台 | 低 | 表格狀態、Toast、抽屜與確認對話框 |
| 審查表單 | 極低 | 證據切換、儲存回饋、錯誤定位 |

### 6.2 動畫時間 Token

```css
:root {
  --motion-fast: 180ms;
  --motion-normal: 420ms;
  --motion-slow: 800ms;
  --motion-path: 1200ms;
  --motion-stagger: 70ms;
  --motion-ease-out: cubic-bezier(0.22, 1, 0.36, 1);
}
```

### 6.3 公開首頁動畫時序

1. 首次進入：標題、說明、按鈕先淡入；資料卡以 `70ms` 間隔交錯進場。
2. Hero 資料卡：緩慢 `translateY` 浮動，幅度不超過 `8px`，避免像廣告 Banner。
3. 滑鼠移入：相關節點、連線與卡片亮起；無關內容降低透明度但不消失。
4. Scroll 到第二段：散落卡片向節點靠攏，連線以 SVG `stroke-dashoffset` 繪製。
5. Scroll 到五年路線：每個年份依序亮起，路徑動畫時間不超過 `1200ms`。
6. Scroll 到下一站：升學／實習／就業三條分岔由同一個節點展開。
7. 最後拼圖：缺漏位置保持可辨識空間，補足後以滑入與填入動畫完成，不做爆炸或大量彩帶效果。

### 6.4 學生端動畫時序

1. 載入首頁：先畫出學生目前年度，再沿路徑載入已存在的成果。
2. 新增成果：表單送出後，新增卡片滑入對應年份，完成度與節點同步更新。
3. 上傳證據：檔案卡由下方進入作品卡，顯示「已經幫你留下來了」。
4. 補件完成：空白拼圖填入、節點亮起、下一個缺口取得焦點。
5. AI 建議：從側邊滑出小卡，以連線指向對應缺漏；不覆蓋主要內容。
6. 作品 Hover：卡片上浮、顯示類型與年份，對應路徑節點亮起。

### 6.5 動畫限制

- 不讓所有元素同時移動。
- 不使用無限旋轉、持續閃爍或沒有目的的彈跳。
- 重要表單、資料表與審查操作不等待長動畫。
- 單一互動完成時間原則上不超過 `1.5s`。
- 動畫必須說明內容關係，例如「這筆成果屬於哪一年」或「這項缺件對應哪個目標」。

### 6.6 減少動態設定

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

關閉動畫時仍必須保留路徑、狀態、缺漏與完成結果，不可只剩空白版面。

## 7. 共用元件規格

- `BaseLayout`：共用字體、背景、頁面容器與無障礙焦點。
- `PublicHeader`：品牌、五年規劃、系統說明、登入。
- `WorkspaceShell`：工作層側邊欄、頂部狀態、內容容器。
- `JourneyPath`：年份、節點、路徑線與目前位置。
- `PieceCard`：成果、證照、課程、活動或專題資料卡。
- `StatusChip`：草稿、已提交、待補件、審查中、已完成。
- `ProgressSummary`：完成狀態與下一步，不只顯示百分比。
- `EvidencePanel`：檔案、連結、證據與來源。
- `AdviceCard`：低存在感 AI／規則式建議。
- `DataTable`：教師與行政使用，支援搜尋、篩選、排序與批次操作。
- `SideDrawer`：教師查看學生、行政查看詳情時使用。

## 8. 響應式規則

| 尺寸 | 版面 |
|---|---|
| ≥ 1280px | 12 欄、展示型不對稱卡片、完整路徑與側欄 |
| 1024–1279px | 8 欄、減少漂浮卡片、保留主要路徑 |
| 768–1023px | 6 欄、側欄可收合、資料卡改為兩欄 |
| < 768px | 單欄、路徑改為垂直、卡片不重疊、動畫減少 |
| < 480px | 主要操作固定在下方或頁首，表格改為卡片列表 |

手機版不可只把桌機畫面縮小；學生的五年路徑要改成垂直軌跡，教師表格要改成可滑動或卡片列表。

## 9. 實作順序

### Phase 1：設計基礎

- 建立 `app/templates/base.html`。
- 建立 `app/static/css/design-system.css`。
- 建立 CSS token、字體、按鈕、卡片、標籤、表單與焦點狀態。
- 建立 `app/static/js/motion.js`，集中處理 `IntersectionObserver`、交錯進場與減少動態判斷。

### Phase 2：展示級畫面

- 完成公開首頁 Hero 與資料卡空間。
- 完成五年路徑與 Scroll 動畫。
- 完成升學／實習／就業分岔。
- 完成學生首頁個人化路徑與缺漏拼圖。

### Phase 3：可操作流程

- 將作品列表、成果表單、證據上傳套用共用元件。
- 新增儲存、提交、補件與 V2 版本動畫回饋。
- AI 建議改為側邊 AdviceCard，不覆蓋主要工作區。

### Phase 4：工作層

- 完成教師工作台、學生詳情、行政模板與審查頁。
- 套用表格、搜尋、篩選、抽屜與批次操作。
- 限制工作層動畫，優先確保資料正確與權限清楚。

### Phase 5：品質驗收

- 檢查台灣口語文案與中國用語。
- 檢查不同文字長度不會破壞版面。
- 檢查 `prefers-reduced-motion`。
- 檢查鍵盤焦點、色彩對比、錯誤訊息與手機版。
- 以首頁 → 登入 → 學生路徑 → 新增成果 → 補件建議完成展示流程。

## 10. UI/UX 驗收標準

- 首頁不再是單一 Hero 加三張卡，而有文字、資料卡、節點與路徑的完整構圖。
- 首頁與學生端至少有三組有意義的動畫：路徑、卡片、節點／拼圖。
- 動畫能解釋資料關係，不只是裝飾。
- 文案讀起來像台灣網路服務，不像機器翻譯或公文。
- 主要頁面保留可探索內容，不因大留白而顯得空洞。
- 教師與行政仍能快速搜尋、篩選、批次操作與完成審查。
- 同一個品牌語言能同時支援展示型頁面與工作型頁面。
- 減少動態後仍能理解所有資料狀態與下一步。

## 11. 提供前端 Agent 的提示詞

```text
請依照「把五年，拼成下一站」設計資管科智慧學習歷程系統。
```
