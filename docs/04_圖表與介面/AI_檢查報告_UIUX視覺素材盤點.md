# UI/UX 視覺素材盤點與首頁方向

> 來源：`docs\99_封存_歷史與待確認\04_視覺參考與聊天紀錄\資管科智慧學習歷程系統---分支-·-網頁設計\chat.md` 與同層 `assets\`。  
> 定位：素材皆作為**設計靈感**，不是可以直接放進正式網站的圖片庫。Pinterest／原作者圖片可能受著作權保護；正式製作應自行繪製、使用有授權素材，或以 CSS／SVG 製作同一種「視覺語言」。

> **2026-09-23 優先順序註記：** 本盤點只規範 P2 視覺與互動呈現；P0 必須先完成成績單／證照上傳、分析與可用文件產出。任何拼圖、路徑或聚焦畫面都必須連到真實分析結果，詳見：[檔案分析與學習歷程產出需求基準](AI_需求基準_檔案分析與學習歷程產出_2026-09-23.md)。

## 一、結論：應採用的視覺主軸

不要做成一般的「科技藍 Dashboard」，也不要把二十張不同風格的圖片混在同一頁。

建議正式定義為：

> **Interactive Editorial Learning Journey**  
> 互動式資訊設計 × 五年成長旅程 × 個人數位檔案

核心隱喻：

| 視覺語言 | 系統意義 | 主要使用處 |
|---|---|---|
| 拼圖 Piece | 一件學習成果：作品、證照、競賽、反思 | 成果卡、完成度、畢業總結 |
| 路徑 Path | 專一至專五及下一站 | 公開首頁、學生個人五年地圖 |
| 節點 Node | 課程、證照、實習、專題等里程碑 | 五年地圖、教師縮圖總覽 |
| 檔案 Archive | 資料被保存、分類並再次使用 | 學生歷程資料夾、作品集 |
| 聚焦 Focus | 依目標校系／職涯突出重要資料 | 升學／就業導航、AI 建議 |

視覺比例建議維持：**70% 安靜乾淨成熟、20% 資訊設計與藝術感、10% 微互動驚喜**。藝術集中在公開首頁、學生首頁、五年地圖與作品集；教師／行政工作頁面以清楚表格與篩選優先。

## 三、頁面與素材的正式分工

### 1. 公開首頁：要吸引國三生、家長與評審

目標不是說「保證上國立大學」；這會變成不負責任的承諾。正確訴求是：

> 讓學生更早看見五年的方向，少在升學、實習與作品整理時重新找資料；把已累積的努力變成能使用的證據。

首頁應採五幕捲動故事，而不是 Hero＋三張功能卡。

| 幕次 | 畫面與動畫 | 對應素材 | 目的 |
|---|---|---|---|
| 1. 資料宇宙 | 小人物／游標周圍漂浮成果卡、細線、可 hover 節點；主標「五年，會留下很多東西。」 | 011、003 | 先讓訪客理解資料分散的問題。 |
| 2. 混亂被整理 | 滾動後卡片由散亂排列為半透明資料層，再收進五個區域 | 001、009 | 不用長篇文字，直接表達系統價值。 |
| 3. 資管五年地圖 | 非直線的專一～專五路徑；每年可展開推薦課程、作品、證照、活動 | 004、008、010 | 讓國三生與家長看懂「資管五年在學什麼」。內容由管理者年度化維護。 |
| 4. 下一站分岔 | 專五後分為升學、實習、就業；點一條路，相關成果被聚焦 | 005、013、019 | 把目標導航變成可看見的功能，而非宣傳詞。 |
| 5. 拼成自己的路 | 碎片聚成完整拼圖／檔案；按鈕「看看我的五年」與「探索資管科」 | 020、006 | 轉換為登入或招生資訊探索。 |

互動限制：首頁可有 1～2 秒的分段捲動過場、hover、點擊卡片、減速移動；必須提供「減少動態效果」選項，手機改成靜態／輕量版本。不可用重型 3D、長影片、全頁自動播放音樂或阻礙捲動的效果。

### 2. 學生端：公開首頁的藝術要變成真實資料

| 頁面 | 視覺做法 | 對應素材 |
|---|---|---|
| 我的五年 | 專一至專五的可展開路徑，節點是真的成果資料 | 004、008、010 |
| 年度資料夾 | 五個學年以 Tab／層疊檔案切換，內有課程、作品、證照、活動、實習、專題 | 006、009 |
| 目標導航 | 選二技／實習／就業後，相關成果亮起、其他成果淡化 | 013、019 |
| 缺漏與完成度 | 空白拼圖代表待補項目；完成後以微動畫補上一塊，文字「又留下了一塊」 | 017、020 |
| 成果新增 | 不用炫技；是乾淨、可預覽、可選類型的表單工作頁 | 014 的清楚感 |

### 3. 教師與科辦／行政：保留品牌，不做藝術展覽

- 使用明確表格、搜尋、篩選、狀態、待補件數與最近更新時間。
- 點入學生後，頂端先顯示縮小版五年地圖，快速看出資料稀疏區，再進入表格與回饋。
- 行政首頁可使用低彩度節點網絡／小型進度圖；實際維護頁保持標準工作介面。
- 適用素材：014、016、001 的「資料層」概念；不要在後台用 3D 場景或大幅動畫。

### 4. 專題簡報與技術頁

- 系統架構、資料流、資料庫與 AI 說明可使用 015 的等角系統視覺語言。
- 這類圖屬於簡報／規格書，不應進入學生每日使用頁面。

## 四、不要再犯的視覺錯誤

1. 不要將流程圖、ERD、資料庫方框當成網站正式視覺。
2. 不要整站塞成相同圓角卡、漸層、統計卡片與紫色 AI 聊天泡泡。
3. 不要把 3D、企業資訊圖、日系插畫、拼貼攝影同時照搬；它們只能共用概念，必須重畫成同一套品牌。
4. 不要把家長／國三生導向寫成「省力保證上國立」；系統可以降低整理成本、幫助學生看懂準備方向，但不保證錄取。
5. 不要只做漂亮公開首頁。學生登入後看到的五年地圖必須是他自己的真實資料，否則會被老師認為只是行銷動畫。

## 五、建議的下一個設計交付物

下一步不要再畫 UML 式流程圖。應先做一份「公開首頁與學生首頁的高保真視覺規格」，至少包含：

1. 首頁五幕每一幕的文案、真實資料來源、互動、手機降級方式。
2. 色彩、字體、線條、資料卡、拼圖、路徑節點、按鈕與狀態的 design tokens。
3. 公開首頁、學生首頁、教師工作台各一張 wireframe／視覺稿。
4. 哪些動畫可用 CSS／JavaScript 完成、哪些刻意不做。
5. 對應實際資料表與 API，確保藝術設計不變成假畫面。

這屬於產品視覺與功能架構的重新收斂。完成並取得使用者確認後，才開始改既有前端。
