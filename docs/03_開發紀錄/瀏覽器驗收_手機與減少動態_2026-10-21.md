# 瀏覽器驗收：390px 手機與減少動態效果（2026-10-21）

驗收者：Claude（任務 C 視窗，分支 `feat/mobile-a11y-check`，基準 `c857e7e`）
對應：`待辦清單.md` 第 8 項「390px 手機、角色導覽及減少動態效果偏好待實測」。

## 驗收環境

- 展示站：`scripts/run_demo.py`（合成資料，SQLite），`DEMO_PORT=5014`，從本 worktree 啟動；主視窗的 5013 沒有動。
- 帳號（皆為假資料）：學生 `111534107`（林小美，已送導師確認，資料最多）、導師 `teacher01`、科辦 `staff01`、管理員 `admin`。確認頁用一張畫布產生的「僅為測試資料 成績單」圖片上傳（假 OCR），沒有用任何真實檔案。
- 瀏覽器：Claude 桌面版內建瀏覽器，視窗模擬 390×844。
- 減少動態效果：內建瀏覽器無法直接切換 `prefers-reduced-motion`，用兩種方式模擬：
  1. **CSS**：把樣式表中所有 `@media (prefers-reduced-motion: reduce)` 規則複製成一般規則套用，再量測每個元素的 `animation`、`transition` 與 `scroll-behavior`。
  2. **JavaScript**：把頁面 HTML 放進全新 iframe，在頁面腳本執行前讓 `matchMedia("(prefers-reduced-motion: reduce)")` 回報 `true`，實際跑 `motion.js`、`components.js` 的減少動態分支（導覽、首頁進場）。
- 量測項目（每頁同一支檢查程式）：整頁是否橫向溢出（`scrollWidth` 是否大於 390）、溢出畫面的元素、被裁切的文字、表格內被擠成一字一行的姓名／欄名、小於 24px 的點擊目標、仍在播放的動畫、浮動「資管科小助手」是否蓋住捲到底的內容。
- 截圖：內建瀏覽器窗格在背景時常截圖逾時（只成功數張），而且背景窗格的截圖右側有裁切誤差；所以本次以版面量測數值為準，截圖只作輔助觀察，不放進 repo。

## 已修

每一項都附重現步驟；修改只有 `app/static/css/design-system.css` 與一個模板，沒有改路由、資料或 JavaScript。

### 已修 1：窄螢幕表格被擠成一字一行

- 重現：390px 以老師登入 `/teacher/dashboard`，學生姓名「王小明」變成寬 17px、高 80px（一字一行），每列高 109px；管理員 `/admin/programs` 的「歷年成績」「自傳及讀書計畫」表頭也一字一行，`/staff/certificates` 的「審核」、`/admin/course-rules`、`/ocr/acceptance` 的欄名同樣被擠。
- 原因：表格寬度 100%，瀏覽器把欄寬壓到中文可斷行的最小寬度（一個字）；外層 `.table-wrap` 雖然可以左右捲，但表格自己先縮小了。
- 修法：760px 以下，`.table-wrap` 內的表頭與按鈕不換行、儲存格 `word-break: keep-all`（中文詞不拆字，遇到標點或空白才換行）。表格變寬後在 `.table-wrap` 內左右捲動。
- 驗證：老師工作台每列高 109px → 53px，姓名一行；上述各頁的擠壓清單歸零。

### 已修 2：自傳「事實清單」的證據編號溢出

- 重現：390px 以學生登入 `/student/autobiography`，「（證據 course:7）」寬 65px 卻落在 2.4rem（43px）的編號欄，清單出現橫向捲動。桌機一樣會發生，只是較不明顯。
- 原因：每列是 `2.4rem 1fr` 兩欄格線，但有三個子項目（編號、文字、`<small>` 證據），第三個自動換到下一列的第一欄。
- 修法：`.facts__list li > small { grid-column: 2; }`，證據編號排在文字欄下方；清單改成只做上下捲動（行尾全形括號在 Chrome 會多算 2～3px 寬，`overflow: auto` 會冒出幾乎看不見的橫向捲軸）。
- 驗證：四筆證據都在 94–347px 內，清單不再有橫向捲動。

### 已修 3：管理員「校系資料」整頁被撐到 563px

- 重現：套用「已修 1」後，390px 以管理員開 `/admin/programs`，`document.scrollWidth` 是 563（整頁可以左右滑）。
- 原因：表格裡的 `.visually-hidden`（「儲存」「對應類別」給螢幕閱讀器的文字）是 `position: absolute`，而 `.table-wrap` 沒有定位，所以這些文字不受捲動區裁切，直接撐寬整頁。
- 修法：`.table-wrap { position: relative; }`。
- 驗證：整頁寬度回到 390。

### 已修 4：老師、科辦、管理員的頂端導覽在手機上黏住大片畫面

- 重現：390px 以管理員登入任一頁，頂端導覽折成多行，高 265px，而且是 `position: sticky`，捲動時一直蓋住 844px 畫面的三成；老師、科辦的導覽也有 171px。
- 修法：760px 以下，非學生版的頂端導覽改為不黏頂（學生版是另外設計的單行導覽，不受影響）。連結仍全部顯示、不用橫向滑動，維持後台的效率。
- 驗證：390px 下 `position` 為 `static`；1280px 下仍為 `sticky`。

### 已修 5：電子獎狀清單沒有頁面標題

- 重現：以科辦登入 `/staff/certificates`，頁面只有 `h2`「待核准的電子獎狀」，沒有 `h1`，螢幕閱讀器的標題清單沒有頁名。
- 修法：`staff_certificates.html` 加視覺隱藏的 `<h1>電子獎狀</h1>`，外觀不變。其他模板都由共用頁首提供 `h1`（量測每頁都讀得到）。

### 已修 6：減少動態效果時，錨點仍平滑捲動

- 重現：把減少動態規則套上後量測 `getComputedStyle(document.documentElement).scrollBehavior`，每頁都還是 `smooth`；點頁內錨點（例如「跳到主要內容」、首頁 `#route`）仍會滑動。
- 原因：全域減少動態規則只關掉 `animation` 和 `transition`，`html { scroll-behavior: smooth; }` 沒有關。
- 修法：減少動態區塊加 `html { scroll-behavior: auto; }`。
- 驗證：每頁量測值變成 `auto`。JavaScript 的 `scrollIntoView` 原本就依偏好切換 `auto`／`smooth`，不用改。

## 問題（未修，留給下一位）

1. **學生首頁導覽第 1 步說明卡壓到目標**：目標「五年路線」高 561px，上下都放不下 160px 的說明卡，`components.js` 的 `place()` 把卡片夾在畫面頂端 12px，蓋住目標上緣約 17px（含高亮外框 8px）。要改的是 JavaScript 定位（例如目標太高時把卡片放到畫面底部、或先把目標捲到卡片下方），超出本任務「只改 CSS／模板」的範圍。
2. **觸控拖曳未實測**：首頁拼圖「缺的片拖回洞裡」在內建瀏覽器只能用滑鼠事件模擬，沒有在真實手機觸控測試。點擊缺片也能直接前往補資料頁，所以不會卡住流程。
3. **老師自傳修改頁未測**：合成資料沒有可修改的自傳版本。
4. **真實裝置與真實偏好設定未測**：本次用模擬方式驗證減少動態，建議期末前再用實體手機開啟系統的「減少動態效果」設定走一次。

## 沒有問題但值得記錄的觀察

- 很多單選鈕、核取方塊只有 13px，但都包在可點的標籤裡，實際點擊範圍足夠。
- 句子中的連結（「改上傳證照」「Google AI Studio」）低於 24px，屬 WCAG 2.5.8 句中連結例外。
- 浮動「資管科小助手」在 520px 以下貼右下角；學生 15 頁都捲到底量測，沒有任何按鈕或文字被它蓋住（頁尾本來就有留白），所以沒有改；展開後在手機上是全螢幕面板。
- `motion.js` 在減少動態下會加上 `reduced-motion` class 並直接顯示進場元素；`components.js` 的路線小人、拼圖、導覽、數字跑動都有判斷偏好。
- 測試時另一個視窗在 `127.0.0.1:5016` 也登入展示站，因為 Cookie 不分埠號，會把 5014 的登入狀態蓋掉；改用 `localhost:5014` 就互不影響。多視窗同時開展示站時要注意。
