## 一、系統定位不變

本專題的完整定位是：協助五專資管科學生從一年級到五年級，持續整理與追蹤學習成果、證照、競賽、實務專題、校外實習、升學備審及就業準備，讓分散在不同地方的資料成為可查詢、可補強、可由教師回饋的學習歷程。

期中不縮減這個產品願景，而是先選出最能證明系統核心價值的一條流程：

```text
學生登入
  → 建立學習成果
  → 選擇學習目標／能力指標
  → 填寫成果說明並上傳證據
  → 保存本次目標要求快照
  → AI 產生初步證據比對
  → 被分派教師查看提交資料
  → 教師逐項覆核並填寫理由
  → 通過／退回／要求補件
  → 學生查看意見並提交 V2
  → 保留 V1、V2、AI 紀錄與教師意見
```

## 二、範圍分層

| 層級 | 定義 | 本專題內容 | 期中處理方式 |
| --- | --- | --- | --- |
| 長期願景 | 五年學習歷程的完整產品方向 | 學習、證照、專題、實習、升學／就業整合 | 保留於正式規格與產品定位 |
| 期中核心 | 必須能操作並可現場驗收的核心價值 | 成果證據提交、目標快照、AI 初檢、教師逐項覆核、補件版本 | 優先完成端到端流程 |
| 期中支援 | 為核心流程提供必要基礎 | 登入、角色權限、測試帳號、教師／學生分派、附件安全存取、操作紀錄 | 與核心流程同步完成 |
| 期末擴充 | 核心流程穩定後再擴充 | 畢業門檻、轉學生抵免紀錄、二技備審、分派通知、統計報表 | 不列為本輪主要驗收 |
| 長期／Future | 需更多資料、規則或校方授權 | OCR、正式校務介接、升學落點分析、進階 AI 推薦 | 不在期中承諾完成 |

## 三、正式規格書章節與期中對應

| 正式規格書位置 | 完整規格內容 | 期中要明確保留或補充的內容 | 狀態判定原則 |
| --- | --- | --- | --- |
| 第一章 緒論 | 五年學習歷程整合、學生與教師面臨的問題 | 說明期中先以成果證據與教師回饋證明核心價值 | 願景不刪除，進度另標示 |
| 第三章 第一節 使用者需求 | 學生、教師／評審、科辦／行政、管理員需求 | 期中先落實學生提交、教師覆核、管理員基本資料維護 | 未實作需求不可寫成已完成 |
| 第三章 第三節 使用者流程 | 學習歷程、AI、招生與升學相關流程 | 將提交快照、AI 執行、逐項覆核、V2 補件標為期中主流程 | 流程圖須與實際畫面一致 |
| 第三章 第四節 權限矩陣 | 各角色可見與可操作範圍 | 驗證學生只能看自己，教師只能看被分派學生，AI 不做正式判定 | 權限需由後端驗證，不只靠前端隱藏 |
| 第四章 第一節 功能性需求 | F-01 至 F-34 完整功能清單 | 標示期中必做、期末擴充與 Future，補上每項驗收條件 | 規劃中不等於已完成 |
| 第四章 第四節 AI 設計與限制 | 多種 Agent 與人工確認 | 期中只做一種證據比對；AI 失敗要顯示失敗且不可產生有效結論 | AI 僅提供建議，教師結論才是正式狀態 |
| 第四章 第五節 驗收原則 | 整體可行性與 AI 測試原則 | 優先驗收一條可展示端到端流程與角色／錯誤測試 | 以操作證據、資料保存與測試結果判定 |
| 第四章 第六節 頁面與路由 | P01 至 P22 | P01 至 P12 是一個月版方向；期中先確保核心畫面可操作 | 頁面編號不是完成度百分比 |
| 第五章 資料表結構 | 完整資料模型與資料字典 | 期中必須對齊提交、快照、附件、AI、分派、覆核、版本與日誌關聯 | 已建立與規劃中分開列出 |
| 第六章 開發時程 | 分階段開發 | 期中以核心流程與交付證據為優先 | 不以總功能比例宣稱完成 |
| 第七章 展示 | 完整系統展示方向 | 準備學生提交到教師覆核再到 V2 的現場展示腳本 | 每個展示步驟都要有可回查資料 |
| 第八章 工作分配 | 組員責任與進度 | 每位組員要有實際可回查的程式、文件、測試或資料庫工作 | 以工作成果，不以百分比表示 |

## 四、期中核心驗收清單

| 編號 | 驗收項目 | 必須看到的證據 |
| --- | --- | --- |
| M-01 | 學生可登入並建立一筆成果 | 登入畫面、成果表單、資料庫紀錄 |
| M-02 | 學生選擇目標並提交證據 | 目標選擇、成果說明、附件或外部連結 |
| M-03 | 提交時保存目標要求快照 | 提交資料中的快照內容與建立時間；修改目標後舊快照不變 |
| M-04 | AI 建立初步證據比對紀錄 | `ai_analysis_runs` 的執行狀態、輸入摘要、結果或錯誤訊息 |
| M-05 | AI 失敗時不產生有效結論 | 失敗狀態、可理解提示、保留人工處理入口 |
| M-06 | 指定教師可查看，未授權教師不可查看 | 分派資料、成功請求與拒絕請求的測試結果 |
| M-07 | 教師可逐項覆核 | 符合／部分符合／不符合／需補件、理由、覆核人與時間 |
| M-08 | 教師可做正式結論 | 通過／退回／要求補件及意見；正式狀態不能由 AI 自動決定 |
| M-09 | 學生可查看意見並重新提交 V2 | 學生端回饋畫面、V2 提交紀錄 |
| M-10 | 歷史資料完整保留 | V1、V2、每次 AI 執行、教師覆核與狀態歷程均可查詢 |

## 六、文件與開發的同步規則

每次新增或修改功能，至少同步檢查以下項目：

- 正式規格書的功能分層與狀態標示。
- `diagrams.md` 中的流程圖、ERD 與角色名稱。
- Data Dictionary 的資料表、欄位與關聯。
- API Specification 的路由、角色與錯誤回應。
- 測試案例中的成功、拒絕與錯誤情境。
- `development-log.md` 的日期、修改檔案、測試結果與下一步。

任何未經科方或老師確認的收件期限、評分標準、正式校務資料與個人資料，均不得自行寫成確定規則。測試資料一律使用假帳號、假密碼與匿名附件。
