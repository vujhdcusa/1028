## 一、必修（依嚴重程度）

### 1. 會議清單 API 讀錯檔案（最嚴重，先修）

- 位置：`server.py` 的 `do_GET` 裡 `url.path == "/api/meetings"`。
- 現況：迴圈已改成 `for p in MEETINGS.glob("*/meta.json")`，但仍寫 `json.loads((p / "meta.json").read_text(...))`，變成讀 `meta.json\meta.json`。
- 結果：清單 API 回錯誤，**左側一場會議都看不到，會議室等於壞掉**。目前 8765 還是舊版所以正常；只要重啟成現在的程式就會壞。
- 修法：改成 `json.loads(p.read_text(encoding="utf-8"))`。
- **補測試**：呼叫會議清單（可抽出成函式，例如 `list_meetings()`），確認回傳每場會議、依 `created` 新到舊排序。這支 API 之前完全沒有測試，所以這個錯誤沒被抓到。

### 2. 同名專案文件再上傳會把舊版蓋掉

- 位置：`save_project_documents()` 直接 `target.write_bytes(raw)`。
- 重現：上傳 `計畫.txt`（內容「第一版」）→ 再上傳同名 `計畫.txt`（內容「第二版」）→ 資料夾裡只剩第二版。
- 違反「不做刪除」原則。修法建議：同名時保留舊版（例如舊檔改名加上時間，或新檔存成 `計畫 (2).txt`），歷史紀錄寫明是新版本。
- 補測試：同名上傳兩次，兩個版本都找得到。

### 3. 上傳名為 `history.jsonl` 的檔案會蓋掉操作紀錄

- 位置：同上；操作紀錄 `project_documents/history.jsonl` 和上傳的文件放在同一個資料夾，`save_project_documents()` 沒有擋這個檔名。
- 重現：上傳一個叫 `history.jsonl` 的檔案 → 原本「誰上傳了什麼」的紀錄被覆蓋。
- 修法建議：操作紀錄改放別的位置（例如 `project_documents_history.jsonl` 或子資料夾），或拒絕保留檔名；`list_project_documents()` 也不要列出紀錄檔。
- 補測試：上傳 `history.jsonl` 後，原本的紀錄仍完整。

### 4. 「確認」按鈕出現在 Claude（主筆）的發言上，按了卻被拒絕

- 現況：前端對所有不是 `you`／`system` 的發言都顯示確認按鈕；但 `confirm_ai()` 只接受 `agents.people()` 裡 `agent` 為真的與會者，`claude-main` 不是，所以回 400「只能確認 AI 的最終功能回覆」。
- 修法：前端只在 `people[m.speaker]?.agent` 為真時顯示按鈕（或後端也允許主筆，二選一，並讓前後端一致）。
- 驗收：Claude（主筆）的發言上沒有按鈕或按了能成功；不會跳出錯誤。

### 5. AI 確認寫進「編輯紀錄」同一個檔案

- 現況：`confirm_ai()` 寫進 `meetings/<會議>/history.jsonl`，和「改會議名稱／議題／目標」共用。
- 造成兩個問題：
  - 編輯紀錄畫面出現「改了「」　改之前（空白）　改之後（空白）」，看不懂。
  - 編輯的版本號是 `len(history)`，有人按確認時版本就加 1，**正在改會議名稱的另一個人存檔會被誤擋**。
- 修法建議：確認紀錄分開存（例如 `confirmations.jsonl`），或版本號只算 `action == "edit"` 的紀錄；編輯紀錄畫面要能看懂確認紀錄（例如「田心于 把 GPT 第 4 則發言列為最終確認」）。
- 補測試：按確認後編輯版本不變；編輯紀錄畫面不出現空白或 `undefined`。

### 6. 搜尋篩選改回了瀏覽器舊式跳出框

- 現況：搜尋篩選「來自特定使用者」「在特定資料夾或會議內」用 `prompt()`，「更多」用 `alert()`。ROOM-01 已經把這類跳出框全部換成網頁內的對話框或選單。
- 修法：改成網頁內的選單（例如列出組員與 AI 讓人點選、列出資料夾與會議讓人點選）。

### 7. 專案文件的存放位置與推送風險

- 現況：`PROJECT_DOCUMENTS = HERE / "project_documents"` 寫死在會議室資料夾，不會跟著 `MEETING_ROOM_DATA` 走，測試時檔案會跑進真的資料夾；而且這個資料夾會被 git 追蹤、推上 GitHub。
- 修法：跟著資料資料夾走（例如 `MEETINGS.parent / "project_documents"` 或另一個環境變數）；在 README 寫清楚這裡的檔案會推上 GitHub、上傳前要確認沒有個資（或決定加進 `.gitignore`——**這一點請問使用者**）。
