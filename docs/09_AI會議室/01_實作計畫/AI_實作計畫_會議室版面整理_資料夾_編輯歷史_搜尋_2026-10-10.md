## 一、硬性規則（違反就停下來，等使用者醒來）

| 規則 | 說明 |
| --- | --- |
| **不做任何刪除功能** | 會議、資料夾、發言、歷史紀錄都**不能刪**。使用者說「寧可專題過了再刪掉」。資料夾只能改名，會議只能搬移、改內容。 |
| **不改發言內容** | 「可以改每個會議的內容」指的是會議的**名稱、議題、目標**；已經送出的發言是會議紀錄，不提供修改（保持可查證）。 |
| **改了什麼都要記下是誰改的** | 用網頁上「學號進場」的組員學號（`members.json`），伺服器端要用 `agents.find_member()` 檢查，不在名單上就擋下。 |
| **路徑一律用相對路徑** | 新增的資料（資料夾、歷史紀錄、搜尋結果、畫面顯示）都不能寫死 `D:\...` 或 `C:\Users\...`。原因：組員還沒下載環境，之後 `git clone` 下來的位置可能不同，不能有檔案遺漏或找不到。見第六項。 |
| **不花 AI 額度** | 測試時**不要**按「請 AI 發言」「全部輪一圈」、不要在會議裡 @AI。要測發言流程就用測試裡的假 AI（參考 `tests/test_parallel_turns.py`）。 |
| **不動其他專案** | 不改 `D:\democase\ai` 的程式碼、資料庫、MySQL；只在 `ai\docs` 寫文件與日誌。 |
| **不推送** | 可以在 `ai-meeting-room` 本機**每完成一項就提交一次**（方便退回），但**不要 push**。推送等使用者醒來決定。 |
| **不要用真資料測試** | 用第〇項的測試資料夾跑測試伺服器，不要在真的會議裡留下測試用的資料夾、改名、搜尋紀錄。 |
| **只測修改過的地方** | 不做整個專案的深度測試、不跑 `ai` 專案的測試。每項做完：補該項的自動測試＋**真的打開瀏覽器**操作該項功能、邊測邊修，通過才算完成。最後跑一次 `python -m pytest tests -q`（會議室測試，十幾秒）。 |

### 1. 右側「與會者」版面整理（使用者：「好亂、看了眼花，做區分就好」）

使用者附的截圖問題：主持人和 AI 混在一起、每位說明文字太長換很多行、浮動的機器人圖示蓋住「Claude（獨立審查）」那一列。

- 分成清楚的兩區，各有區塊標題與不同底色或框線：
  - **主持人（專題組員）**：三位組員，組長在最上面，「換人」按鈕。分工說明縮成一行（太長就截斷，滑鼠移上去看全文）。
  - **AI 與會者**：Claude（主筆）、Gemini、GPT、Claude（獨立審查）、自訂 AI。狀態（待命／發言中／排隊／離席）用圓點＋短字；「本場主筆」用小標籤；CLI 名稱、模型等次要資訊放第二行小字或滑鼠移上去才顯示。
- 按鈕（🔇、⏹）對齊在右側，不要擠壓名字。
- 浮動的機器人圖示**不能蓋住內容**（移到不擋的位置、縮小或可以收起來）。
- 不改功能，只改呈現；原本的 `data-mute`、`data-stop`、點名字編輯 AI 都要照常能用。
- 驗收：瀏覽器在寬版（約 1400px）與右欄縮窄（約 320px，同截圖）各截一張圖確認不擠、不重疊；按 🔇／點 AI 名字仍正常。

### 2. 會議資料夾分類（像 Discord 的伺服器）＋搬移會議

- 左側會議列表的最左邊加一條窄欄，放「資料夾」圖示（像 Discord 左邊的伺服器列）：最上面「全部」，下面是各資料夾，最下面「＋ 新增資料夾」。點資料夾只顯示裡面的會議。
- 資料夾欄位：代號、名稱、圖示（emoji 或顏色）、建立者學號、建立時間。存在 `meetings/` 底下的一個 JSON 檔（例如 `meetings/folders.json`），**要被 git 追蹤**（`meetings/` 已經會推上 GitHub，組員下載就有）。
- 會議的資料夾記在該會議的 `meta.json`（例如 `"folder": "<資料夾代號>"`）；沒有資料夾的會議顯示在「未分類」。
- 主持人可以把會議**搬到**某個資料夾：會議的設定選單裡選「移到資料夾」，有餘力再做拖曳。
- 資料夾可以**改名、換圖示**，**不能刪除**。
- 每次新增資料夾、改名、搬移都寫歷史紀錄（見第 3 項的格式），記下學號與時間。
- 驗收：瀏覽器新增兩個資料夾 → 把一場會議搬進去 → 切換資料夾只看到該會議 → 改資料夾名稱 → 重新整理頁面後狀態都還在；介面上找不到任何刪除按鈕。

### 3. 改會議名稱／議題／目標＋歷史版本

- 會議標題旁或議題區加「✏️ 編輯」：可以改**名稱、議題、目標**。
- 每次儲存都追加一筆歷史紀錄，**只增不改不刪**：時間、學號（顯示組員姓名）、改了哪個欄位、改之前、改之後。建議存在 `meetings/<會議編號>/history.jsonl`；資料夾的變更存在 `meetings/folders_history.jsonl`（或類似名稱）。
- 有「📜 編輯紀錄」可以看這場會議所有的修改：誰、什麼時候、改了什麼（改前／改後並列，或標出差異）。
- 防止兩個人同時改互相覆蓋：儲存時帶上目前版本（例如歷史筆數或最後修改時間），不一致就回「已經有人改過，請重新整理」並保留使用者剛打的字。
- 會議裡同時留一則系統訊息，例如「主持人 田心于 把會議名稱改成『…』」，讓 AI 也看得到。
- 驗收：瀏覽器改名稱與議題 → 編輯紀錄出現兩筆、顯示正確的組員姓名 → 用另一個分頁開舊頁面再存 → 被擋下且打的字還在；沒有學號（清掉瀏覽器的學號）時不能存。

### 4. 搜尋（像 Discord 的搜尋）

- 上方加搜尋框（快捷鍵 `Ctrl+F` 可選做），可以跨所有會議搜尋：會議名稱、議題、發言內容、附件檔名。
- 支援像 Discord 的篩選寫法，輸入時有提示：
  - `from:` 發言者（AI 名稱或組員姓名／學號）
  - `in:` 資料夾名稱（或會議名稱）
  - `has:附件`
  - `before:` / `after:` 日期（例如 `after:2026-10-09`）
- 結果顯示在側邊面板：會議名稱、發言者、時間、前後文片段（關鍵字標亮），依時間新到舊。點一筆就跳到那場會議的那則發言並短暫標亮。
- 後端新增搜尋 API，只讀 `meetings/` 底下的檔案；結果中的位置用「會議編號＋發言編號」，**不要回傳本機絕對路徑**。
- 驗收：瀏覽器搜尋一個已知的詞 → 點結果跳到正確的發言 → `from:` 與 `in:` 篩選各試一次 → 搜不到時顯示「找不到」而不是空白。

### 5. 相對路徑與「組員重新下載也不缺檔」

背景：`workspaces/`（程式碼快照）不會推上 GitHub；會議的 `meta.json` 目前把專案資料夾存成絕對路徑（例如 `"repo": "D:\\democase\\ai"`），檔案面板沒有快照時會改讀這個路徑。組員下載的位置不同，就會找不到。

- 新建會議時，專案資料夾和會議室在同一層（例如都在 `D:\democase` 底下）就存相對路徑（例如 `../ai`，相對於會議室資料夾）。
- 讀取時統一經過一個函式解析：相對路徑 → 以會議室資料夾為基準；舊的絕對路徑存在就照用；**不存在時改找會議室旁邊同名的資料夾**（例如 `D:\democase\ai` 找不到就找 `<會議室上一層>\ai`）。
- 檔案面板顯示的來源路徑改成相對路徑（例如 `../ai/app/routes/teacher.py`、`workspaces/<會議編號>/...`），不要露出 `C:\Users\...`。
- 新增的資料檔（資料夾、歷史紀錄）確認都**有被 git 追蹤**：`git status` 看得到、`.gitignore` 沒有擋掉。
- **驗收（重要）**：把本機 repo `git clone` 到暫存資料夾的「另一個位置」，旁邊不放 `workspaces/`，用另一個埠號啟動，瀏覽器確認：會議列表、資料夾、編輯紀錄、搜尋都正常；檔案面板會改讀旁邊的專案資料夾或清楚顯示「找不到專案資料夾，請把 ai 放在會議室旁邊」，不會報錯或空白。
- 補自動測試：相對路徑解析、舊絕對路徑找不到時改找同名資料夾。
