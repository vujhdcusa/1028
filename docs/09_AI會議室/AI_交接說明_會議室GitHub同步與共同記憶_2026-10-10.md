## GitHub 交付範圍

會議室專案遠端：

```text
https://github.com/LanyuLiu951127/ai-meeting-room.git
```

本次應提交的程式內容：

- `README.md`
- `server.py`
- `agents.py`
- `static/index.html`
- `document_extract.py`
- `requirements-document-preview.txt`
- `tests/`

組員 clone／pull 後仍需自行執行：

```powershell
python -m pip install -r requirements-document-preview.txt
python -m pytest tests -q -p no:cacheprovider --basetemp=.tmp\meeting-room-tests
.\啟動會議室.bat
```

組員會得到相同的程式功能與 UI，但不會自動得到：

- `meetings/` 內的逐字對話、附件與 AI 原始輸出。
- `workspaces/` 內的本機快照。
- `agents.json`、`settings.json`、`quota.json` 與各家 CLI 登入狀態。

這些檔案目前由 `.gitignore` 排除，是刻意避免把私人路徑、附件、金鑰／登入狀態與大型快照推上 GitHub。

## 共同記憶的正確邊界

會議室適合當作即時頭腦風暴與互審場所；GitHub 適合保存團隊確認過的共同知識。每場會議結束後，主筆應把以下內容整理進 `D:\democase\ai\docs`，再由專題 repo 提交：

1. 決策與理由。
2. 已確認的規格或實作結果。
3. 證據檔案／程式位置。
4. 尚未解決的風險與下一步。

下一場會議先讀這些已提交文件，再把它們作為專案背景或附件。不要直接解除 `meetings/` 的忽略規則；若要共享完整對話，應先做去識別化與本機路徑清理，再匯出成可審閱的共同記憶文件。
