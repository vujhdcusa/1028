## 系統定位

本系統不是一般作品集網站，而是為五專資管科學生五年學習期間設計的「成果證據與教師回饋」系統。應整合課程成果、證照、競賽、實務專題、校外實習、升學備審、畢業門檻與轉學生抵免等資料；但期中開發必須縮小為可驗收的核心流程。

康寧資管科特色與需求方向：

- 資訊軟體開發、資料庫、網站與系統測試等實作能力。
- 商業管理資訊化與資訊管理能力。
- 醫療資訊管理特色。
- 證照、競賽、實務專題、校外實習、升學與就業的長期學習歷程。
- 五專生需要能從一年級到五年級查看自己累積的成果及畢業準備進度。

## 指導老師已確認的核心要求

本組為「03 學習歷程組」，老師定位如下：

- 核心主題：成果證據與教師回饋。
- 核心功能：主張與證據比對、教師逐項回饋。
- 要把「目標要求快照、分派、提交、覆核」放在同一套資料模型中。
- 三位組員先集中完成一種 AI 檢核流程；不要同時開發整套龐大的學習歷程功能。
- 不可只說整體完成 70%；期中報告應說「已驗收 X 項／期中必做 Y 項」。
- 功能完成的驗收條件：前端可操作、後端有驗證、資料真的儲存、角色與錯誤測試完成、有可展示證據。
- AI 服務失敗時要顯示失敗狀態，不可產生有效結論；錄製結果只能標示為備援。
- 四週內優先減少資料量、外部串接、畫面美化；不能移除後端權限與專題核心流程。

### 老師特別會追問的問題

1. 系統說支持，是支持有一份文件，還是支持學生真的會寫程式？
2. 教師駁回 AI，是否代表學生一定正確？
3. 修改目標規則後，已提交學生的完成率會不會突然改變？
4. 未被分派的教師直接開附件網址時會怎樣？
5. 同一份資料跑三次 AI，哪一份報告被教師看過？
6. 沒找到證據，為何不能直接說學生造假？
7. 原本承諾的評分鎖定現在在哪裡？
8. 組員各自負責哪一段；新增一個必填欄位會影響哪些地方？

## 期中必做核心流程

```text
學生登入
→ 新增一筆學習成果
→ 選擇對應的學習目標或能力指標
→ 填寫成果說明、上傳附件
→ 系統保存當次目標要求快照
→ AI 產生初步「證據比對」結果
→ 教師在待審清單開啟該筆提交
→ 教師逐項覆核 AI 結果
→ 教師選擇通過／退回／要求補件，並填寫意見
→ 學生查看意見後重新提交 V2
→ 系統保留 V1、V2、AI 執行紀錄、教師意見與狀態歷程
```

### 必要商業規則

- 提交時一定要保存「目標要求快照」。之後管理員修改目標或規則，舊提交不能被覆蓋或改變。
- 每次重新提交建立新版本；V1 不可被 V2 覆蓋。
- 每次 AI 執行建立獨立紀錄，教師覆核時要能知道看的是哪一次結果。
- AI 僅提供初步建議，不能自動判定學生通過，也不能把「找不到證據」說成學生造假。
- 教師的覆核結論才是正式狀態；教師可不同意 AI。
- 教師只能看到自己被分派或被授權的學生與提交資料；附件不能靠猜網址直接取得。
- AI 失敗、附件無法讀取、欄位不足都要留下可理解的錯誤狀態與提示。

## 教師端不可過弱 必要畫面

1. 教師工作台：自己的待審件數、待補件件數、最近審查。
2. 待審查清單：可依班級、學生、狀態篩選。
3. 學生提交詳情：成果主張、附件、當次目標快照、版本清單、AI 執行紀錄。
4. 逐項覆核頁：每一項證據可標記「符合、部分符合、不符合、需補件」，並填寫理由。
5. 審查結論：通過、退回、要求補件；意見會回到學生端。
6. 版本與歷程：明確顯示 V1、V2、每次提交時間、AI 執行時間、教師覆核人與結論。
